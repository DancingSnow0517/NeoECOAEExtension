# ECO 大宗存储（MEGA Cells 联动）

适用：Minecraft 1.21.1 / NeoForge，当前源码。

## 已采用的规则

25/50 类大宗盘和扩展卡仅在检测到 MEGA Cells 安装后，通过 MEGA Cells 集成入口注册；组装和拆解配方使用同样的模组加载条件。压缩能力仍由 ECO 内置，ECO 存储主机向 AE2 提供虚拟转换样板，不需要压缩卡、解压模块或实体工作台。旧 LE4/LE6/LE9 单类大宗盘及共享转换样板载体继续由基础模块注册，以保留旧盘功能。

每盘默认 25 个资源标记位，安装一张 ECO 大宗扩展卡后为 50 个。同一条压缩链只占一个资源类型。普通无压缩关系的物品也能手动标记；自动标记只选取具有已识别压缩关系、且数量超过阈值的资源。仍使用现有 ECO 标记界面，Shift + 左键/右键切换展示形态。

内部数量及累计换算因子使用 `BigInteger`，不设物品数量上限。AE2 的普通存取接口仍使用 `long`：每次操作最多 `Long.MAX_VALUE`，多次操作可以继续累计。库存报告仅在这个接口边界饱和，ECO 精确数量通道提供真实数值。库存是有限的实际存入数量，不是创造供应源。

主盘为 L9，待机耗能沿用 1,024 AE/t。保留的 LE4/LE6/LE9 旧大宗物品 ID 也使用新库存实现，但保留单类资源限制与原待机耗能，不接受扩展卡；它们继续隐藏在创造标签页之外，读取原有实际物品数量，并保留原有组装、拆解配方。这些盘不参与无限存储域的有限盘迁移。

## 资源计数与库存展示

一条铁资源链的换算表为铁粒 `1`、铁锭 `9`、铁块 `81`。插入一种形态时，将数量乘以对应因子，加入该资源账户的基础单位余额。提取时先计算能取出的完整物品数，再扣除这些物品对应的单位数，任何余数都保留。

盘对外公布互不重叠的库存。截止形态是铁锭、余额为 `109` 基础单位时，网络看到 `12` 锭和 `1` 粒；截止形态改为铁块后，网络看到 `1` 块、`3` 锭和 `1` 粒。不会同时报告三种完整等价数量，也不会因为显示饱和而删除隐藏在其后的真实数量。

截止形态改变展示与虚拟配方方向，不改变持久化余额。盘本身允许直接提取同链的其他形态；AE2 的合成规划则根据互不重复的已公布库存及虚拟配方获取其他形态。

## 自动识别与数据包

服务器启动和数据包重载后，从常规有序/无序工作台配方中识别压缩关系：

1. 所有非空输入槽都必须接受同一个完整物品键；空槽不计入转换比例。
2. 压缩结果必须是一个物品，且输入数量至少为两个。
3. 必须存在一份输入恰好返回原物品和原数量的反向配方。
4. 使用实际输入检查配方匹配、实际输出及剩余物；有容器返还、动态特殊语义或不支持的自定义成分时不自动接入。
5. 物品键包含 Data Components。不会将同 ID 的不同组件物品自动合并。
6. 分叉、循环、相互冲突的比例会使整组关系被拒绝，不按配方加载顺序任意挑选。

机器配方不在自动扫描范围内。整合包可以在 `data/<命名空间>/eco_compression/<文件名>.json` 显式添加转换或排除物品：

```json
{
  "disabled": [
    { "id": "minecraft:coal" }
  ],
  "conversions": [
    {
      "lower": { "id": "minecraft:iron_ingot" },
      "higher": { "id": "minecraft:iron_block" },
      "ratio": 9
    }
  ]
}
```

`lower`、`higher` 和 `disabled` 使用 Minecraft ItemStack 格式，数量必须为 `1`，可携带组件。`ratio` 是一个高阶物品对应多少个低阶物品，至少为 `2`。显式规则覆盖对应的向上、向下相邻关系，仍经过链的冲突检查。数据包作者需保证显式转换符合整合包实际规则；它可以授权自动识别范围之外的转换。

## 自动合成与产物归属

在已形成、已供电并接入 ME 网络的 ECO 存储主机内，主机为本机大宗盘发布虚拟转换样板。主机必须处于普通存储模式；切换到 IO 转移模式、无限域模式或结构失效时撤回样板。

截止形态以下的相邻关系提供向下拆分，截止形态及以上提供向上压缩。铁锭为截止形态时，提供 `1 锭 → 9 粒` 和 `9 锭 → 1 块`。相同转换去重，主机存储优先级同时作为样板优先级。

普通 AE2 执行路径校验收到的完整输入；ECO FastPath 校验每份输入、输出和批量总数。只有仍由该主机内的盘提供的有效样板可以接收任务。虚拟样板有自己的编码载体和解码器，供 CPU 保存和恢复。

接受输入后，转换产物立即记入接收盘的待回填队列。队列使用精确整数并随盘持久化；后续 tick 按网络实际接收数量扣减，满网时保留剩余产物继续等待。换主控、卸载区块、重启或网络分裂不会复制网格公共队列。盘被取走后暂停回填，重新装入有效主机后继续。含待回填产物的盘不能拆解。

## 旧盘与配方变化

主盘和扩展卡保留历史 ID `neoecoae:eco_mega_long_bulk_cell`、`neoecoae:eco_mega_upgrade_card`，名称显示为 ECO 大宗存储矩阵、ECO 大宗扩展卡。两者仅在安装 MEGA Cells 后注册，库存与转换逻辑使用 ECO 自身实现。

新库存使用 `neoecoae_bulk` 的第 2 版数据，数量和累计因子保存为十进制字符串。可读取旧的 `neoecoae_mega_long_bulk` 第 1 版长整型数量和换算表，以及普通旧盘的 `STORAGE_CELL_INV` 实际数量。普通旧盘的实际数量先按原物品保存，不把旧物品数量误当作粒级单位。

每个账户保留当时的不可变换算表。重载后如果表发生变化，不按新比例解释原余额；暂时只允许按原表最小形态取回，并阻止向同一资源继续混入新比例的数据。原表恢复后可恢复形态转换。必须清空旧账户后，才能采用新表重新存入。

缺失物品、无效组件或无法确定历史基准的条目原样隔离保存，界面提示不可用。重新加载盘，或配方快照变化时重试恢复。没有历史表的第 0 版数据只有在能识别其原有基准时才迁移；无法识别时保留原文，不猜测比例。仍有隔离数据时不能拆解。

## 主盘配方

主盘通过集成工作站使用 ECO 大宗外壳、ECO 256M 存储组件、8 个 AE2 工程处理器、64 个奇点组装，能耗为 144,000。拆解空盘返回外壳和存储组件。

扩展卡通过集成工作站使用 AE2 高级卡、ECO 256M 存储组件、8 个工程处理器制作，能耗为 288,000。所有输入仅引用 NeoECOAE 和 AE2。
