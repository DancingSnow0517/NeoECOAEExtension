# 精确数量计算

规划、循环方程、供给证明、种子预留、执行账本、精确库存、数量汇总和数量排序统一使用 `PlannerAmount`。批量存储账本、压缩单位换算、存储恢复模拟、字节容量计算、工作站整数费用、合成报表、存储图表和 ETA 也使用分层数量。共享存储数量 `HugeAmount` 使用同一 `U128` 中间层。

数量按实际大小选择三个层级，并在结果缩小时自动降级：

| 层级 | 范围 | 计算方式 |
| --- | --- | --- |
| long | 有符号 long 范围 | 原生整数运算 |
| 双 long | 绝对值小于 2^128 | 两个 long 保存 128 位幅值，差额的符号单独保存 |
| BigInteger | 绝对值达到 2^128 | 任意精度兜底 |

`U128` 处理完整的进位、借位、无符号高位乘法及除法。long 除数采用 2^32 基数的两位商算法，避免逐位迭代 64 次；双 long 除数采用原生字移位减法。商和余数可在一次运算中计算。哈希直接读取整数位，不再为原生层创建 BigInteger。

存储表的可变数量继续直接更新两个 long，原来的 126 位阈值扩展到完整 128 位。读取快照和字节统计共享原生幅值，不再经过 BigInteger 转换。高位为负的 Java long 代表无符号位模式，进位溢出到 2^128 后才进入兜底层。

AE2 和第三方接口的 long 窗口、公开 BigInteger 数据接口以及存档编码仍是输入输出边界。窗口内的批次必须满足 long 上限；订单总量和跨批次账本保持精确。公开兼容接口在入口转换数量、在出口转换结果，内部账本持续使用原生层。分数能源预算及显示舍入使用 BigDecimal，整数份数进入预算和离开预算时与分层数量转换。

## 大单汇总修复

加工派发在循环内逐批结算。循环结束仅返回累计接受份数，避免再次将整笔订单产物或返还物重建为 long 总量。单份产物、返还物在一次访问开始时读取，后续批次复用，减少重复复制和排序。

## 微基准

工具位于 `tools/amount-benchmark/AmountBenchmark.java`，使用 Java 17，可直接针对生产 JAR 编译、运行。预先生成 4096 个整数；每个整数执行 `+17、×5、-17、÷131` 并计算哈希。预热后交替测量两条路径，以下为五轮中位数，每轮 50 万条运算链。

2026-11-07 针对最终 `neoecoae-20.5.5.jar` 的本机测量，Java 17.0.10，堆大小 128–512 MiB：

| 输入位数 | 直接 BigInteger | 分层数量 | 对比 |
| --- | ---: | ---: | --- |
| 60 | 22.00 ms | 1.93 ms | 约快 11.4 倍 |
| 96 | 31.46 ms | 17.12 ms | 约快 1.8 倍 |
| 124 | 30.02 ms | 17.24 ms | 约快 1.7 倍 |
| 192 | 40.29 ms | 56.82 ms | 约慢 41% |

这是独立整数运算链的测量，不等同于整单规划耗时或游戏吞吐量。超过 128 位的路径仍有数量对象及接口转换成本。原生 long 链在这个基准中被 JIT 消除了临时分配；存入真实集合的数量对象仍会分配。

## 回归范围

已有算术性质测试以 BigInteger 为对照，覆盖三个层级、正负数、Long.MIN_VALUE、128 位边界、乘除、余数、进位、借位、哈希及降级。大单回归验证多个合法批次的累计产物或返还物超过 long 后仍精确记账。保存恢复覆盖 67、127、128、129、1024 位数量；进度统计覆盖混合单位及超出 double 范围的数量。外部供给回归验证无限库存的累计消耗超过 long 后保留已求解的精确数量。

最终完整测试的 XML 报告统计为 2377 项，0 失败、0 错误、19 跳过。Java 17 的 combined 配置已完成 `test`、`jar`、`sourcesJar` 和 Forge 重映射。JAR 包含新的 `U128`，无旧 `U126` 类；分层算术与编译输出的指令和控制流在排除 Forge 重映射造成的常量池编号及加载指令宽度差异后相同。构建和测试不代表游戏内验证，尚未测量真实整单耗时或吞吐。
