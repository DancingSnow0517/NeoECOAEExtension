# 合成派发取料性能优化

适用于 Minecraft 1.21.1 / NeoForge。本文记录 2026-10-27 对 ECO CPU、原生 AE2 / OmniCell CPU 与 AdvancedAE 外部 CPU 快速批量通道的优化；版本号未因此变更。

## 问题与实现

外部 CPU 原先会为每个待处理样板创建 `ListCraftingInventory`，再执行 `preview.list.addAll(inventory.list)`。复制完成后才检查样板是否存在可用的 ECO 批量提供器。CPU 内部无关物料越多，每次尝试的成本越大；每成功发配一批便返回，还会让外层 CPU 循环重新扫描前面的任务。

本次采用以下处理：

- 在解析材料之前检查提供器是否支持 ECO 快速批量或已注册的并行契约，以及实时阻挡、忙碌状态；没有可用目标时跳过取料。
- 外部 CPU 复用 `ECOCraftingInputPreview`。真实库存保持不变，预检查只记录本次输入实际涉及的虚拟扣减；重复输入槽共享扣减记录，不能重复使用同一份库存。
- 保留 AE2 的候选材料枚举与 `IInput.isValid` 校验，以及容器返还语义。每次尝试读取实时库存和有效性；不缓存“忙碌”“缺料”之类可能变化的结果。返还物映射复用既有的数据包重载感知缓存。
- ECO CPU 调度器与外部 CPU 都使用各自的 `ECOCraftingInputBuffer`，复用输入计数器、数组、预期输出和返还物计数器。新一次解析清空旧内容，并清理空子索引，避免旧材料残留或无限累积。
- 提交给提供器的批量上下文仍物化为独立材料快照；后续复用取料缓冲不会改变已经接受的批次。批量上下文的转换改为预分配数组与显式循环。
- 外部 CPU 一次任务遍历可以处理多个就绪样板，返回实际成功发配的批次数。每个接受的批次仍占用一个原生 CPU 发配槽；剩余槽位由 AE2 / AdvancedAE 原有外层循环继续使用。
- 外部 CPU 的等待量溢出预检查复用原始数量映射，保留同键输出与返还物合并后的精确溢出检查。

实体输入只在已有批量事务提交阶段扣除。提供器明确拒收时回滚材料与能量，接受状态不确定时暂停任务并保留所有权，避免重复发配。ECO 调度状态在回调中重置时会替换取料缓冲，正在结算的调用继续持有原缓冲，避免清空尚未完成的记账数据。

## 发配速度与限制

本次没有增加每 tick 扫描额度、成功批次数上限或批量大小上限。外部 CPU 会在调用方传入的 `maxPatterns` 原生额度内继续工作；超过 1,024 个无可用目标的样板之后，仍可在同一次调用找到并发配后面的就绪任务。

ECO 自身调度器此前已有每次 `execute` 最多检查 64 个候选、游标续查和现有发配预算；本次没有修改这些调度规则。这里优化的是取料与临时对象，不调整玩家既有的协处理器、并行、能耗、循环种子或加工时长规则。

GTO 参考范围为 GTOCore `2cd0d07` 的 `OptimizedCraftingCpuLogic`，以及 AE2 GTO fork `974a922` / `15.2610.41`。借鉴其按样板取料、复用计数器和单次遍历处理多个任务的做法。GTO 的直接扣料回填不能原样搬入 ECO 的批量事务；本实现通过虚拟扣减保留 1.21.1 的材料匹配和实体所有权边界。GTOLib 私有子模块未初始化且远端不可访问，未据此推断其内部实现。

## 基准

`ECOCraftingInputPerformanceTest` 在同一 JVM 中交替比较旧的全库存副本与新的可复用虚拟取料。使用实际 AE2 库存与物料键，样板包含三个输入槽，其中两个槽消耗同一物品，另一个槽带桶返还。无关库存使用 1、1,000、10,000 个带不同组件的石头键。

每组先预热，再交替记录七轮的耗时和当前线程分配字节。时间用于报告，不作为测试通过条件。以下为本机 JDK 21 的一次运行中位数：

| 无关库存条目 | 旧取料预检查 | 新取料预检查 | 旧分配量 / 次 | 新分配量 / 次 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 5.117 微秒 | 2.790 微秒 | 8,064 B | 3,584 B |
| 1,000 | 69.200 微秒 | 4.826 微秒 | 32,472 B | 3,584 B |
| 10,000 | 118.310 微秒 | 0.871 微秒 | 204,048 B | 3,104 B |

小样本之间的耗时受 JIT 与 GC 影响，不能据此推断整个服务器的 TPS 或崩溃前 60 秒的耗时占比。10,000 条目组的单次分配量减少约 98.5%；确定性回归另外验证 4,096 个无关键不会在取料期间被重新哈希，且真实库存不被预检查扣减。

复现命令（先将 `JAVA_HOME` 指向有效的 JDK 21）：

```powershell
.\gradlew.bat test --tests '*ECOCraftingInputPerformanceTest' '-Dcrafting.performance=true' --offline --console=plain
```

原始报告输出到 `build/reports/crafting-input-performance.csv`。正常测试默认跳过基准。

## 回归范围

- AE2、OmniCell、AdvancedAE 的一槽多份批量结算、工作站并行契约与任务 ID。
- 无提供器、普通提供器、忙碌或阻挡提供器均不触发材料解析。
- 同一 tick 连续 128 批仍保留每批 512 份能力；一次遍历填满两个原生发配槽，并避免重复扫描前面的无可用目标任务。
- 同料多槽不足与充足场景、模糊候选有效性、容器返还、失败重试、输入槽数量变化和源库存替换。
- 输入缓冲复用之后，已物化批次快照仍独立；拒收、能量变化、等待量溢出和不确定接受状态维持原事务行为。

这些验证属于源码、JVM 回归与局部性能基准；尚未在原崩溃存档中进行游戏内复现或 TPS 验收。
