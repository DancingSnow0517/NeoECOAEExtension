## 结论

建议同步，按“正确性修复 → 存储扫描与终端同步优化 → 大型工作站行为和界面 → 主机面板扩展 API”分批处理。

## 第二批：存储扫描与终端数量同步

建议成组同步 `77f56abb1`、`89db599f5`，参考说明 `3422f77cf`。

当前 `NetworkStorageMixin` 仍为每个挂载库存新建临时 `KeyCounter`，`ExactAmountCollector`、`ExactAmountSource`、`TerminalExactAmountSync` 与原基线文本一致。新增加的 `StorageListingAccumulator`、`TerminalInventorySnapshot`、`SupplierStorageAccessor` 在目标工程中尚不存在。

同步收益来自普通扫描复用计数器、普通 long 数量避免不必要的大数运算、同库存多终端共享快照，以及仅为无限/超 long/普通投影失真的数量发送精准侧通道。它不要求改变 SavedData 文件格式。

应保持以下合同：过滤存储不能与未过滤库存共用快照；子网络只计数一次；旧快照发布后只读；传输繁忙或失败时不推进同步基线；数量回落到普通范围时删除精准侧通道条目；来源切换与时钟回退时重建基线；停止服务时清理缓存。

第一批无限域访问封锁完成后再验证扫描快路径，确保声明“可直接饱和追加”的库存仍遵守动态访问限制。Bigger AE2 类的专属适配和测试继续按目标工程范围裁剪，通用终端优化可独立保留。

上游性能说明使用 Java 21 / AE2 19 的局部扫描和独立服务端数据。本轮没有复跑性能测试；这些数值不能直接作为 Java 17 / AE2 15 的耗时或整服 TPS 结论。

## 第三批：大型工作站行为与界面

建议将行为改动 `597c51c5a`、`5ddc867c0`、`0a37b8af6`、`150eb552f` 作为同一组设计目标处理：

1. 满载升温从随温度变快调整为先快后慢；电预热跟随热曲线，并显示最近 20 tick 的实际加工产热、预热、主动/自然散热与净变化。
2. 温度或冷却液升档后，从连续队首的同任务、同配方、同单位投入产出批次补满可用并行；已付工作量和进度余数继续有效。
3. 温度跌破原批次门槛后，剩余工作可按最多 256 次一段继续执行；材料、产物和额外兼容输入按实际段结算。
4. 温度恢复原批次门槛后解除临时分段，恢复原并行。`0a37b8af6` 的早期“之后永久 256”行为已由 `150eb552f` 修正，不能只移植前一个提交。

这组改动涉及 `PendingBatch` 的新增持久化字段 `progressRemainder` 和 `segmented`。应明确旧字段缺省值、反复升降档、温度/冷却液模式切换、已付能量、输出阻塞、取消/拆除时成品与未加工输入同时存在的处理。先固定这些暂停与恢复规则，再确认热曲线参数；不能只修改热曲线常量。
