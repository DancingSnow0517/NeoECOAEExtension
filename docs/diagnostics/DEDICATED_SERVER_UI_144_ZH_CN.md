# #144 专服公共 UI 与菜单生命周期修复

本记录针对 Forge 1.20.1 分支，问题来源为本仓库 #144。此前 #139 的远程机器 UI 修复保留。

## 改动

- 共享 `IGuiTexture.EMPTY` 使用显式空纹理对象，避免在接口初始化时解析包含 `GuiGraphics` 的 lambda 签名。绘制实现和客户端便利入口使用 Forge 分端标记，保留客户端绘制行为。
- 普通计算界面与 CPU 选择器在专服仅构造滚动条几何和状态；AE2 原生滚动条、样式、绘制和鼠标事件留在物理客户端。
- 公共 `block_ui` 打开包同时传输位置与服务端方块状态。普通/大型工作站根据同一快照构建控件树，避免客户端块状态更新滞后时按错误分支读取初始数据。
- holder 记录原方块实体身份。实体被替换、移除或区块卸载后立即失效；按钮、数据绑定和原生槽操作检查 holder，不必等到下一次菜单广播关闭后才停止处理。
- 原生槽的显示/布局状态继续由 `isActive` 控制，物品取放与自定义点击另行检查有效菜单。被拒绝的点击返回非 null 空栈，阻止 LDLib 继续走原版点击回退。
- 网络协议提升为 `4/<mod_version>`，使新的 `20.5.2` 与旧同名 `3/20.5.2` 构建在连接时明确拒绝混用。客户端与服务端须配套更新。

## 验证

使用 Forge 实际 `RuntimeDistCleaner` 的 3 项分端回归在修复前均失败，修复后通过；另有状态快照、方块实体替换、移除、区块卸载，以及有效/失效菜单按钮和原生槽位的正负对照。原有样板槽测试补齐有效菜单上下文，保留其取放物资断言。

Java 17.0.10 / Forge 47.4.28 / AE2 15.4.11 / LDLib 1.0.52.a 的独立专服实际进入隔离世界后：

- 14 条公共方块菜单路由各构造和重新打开 2 次，共 28 次菜单构造、28 次 factory 打开，0 失败。
- 真实搭建大型集成工作站后，故意将接收侧世界设为旧状态，状态快照仍选择 127 个控件、947 bytes 初始数据的大型树。
- 有效菜单完成 3 个石头的原生取出/放回，按钮与自定义槽点击正常执行；同位置替换同型号方块实体后，广播关闭前已拒绝旧按钮和槽位操作，原物资数量不变，随后菜单关闭。
- 1 条使用 AE2 原生菜单的独立路由显式跳过，不计为公共 UI 通过。

完整 Java 17 `build` 通过：2100 项测试，0 失败、0 错误、18 项跳过。发布 JAR 的版本号为 `20.5.2`，本工程类为 Java 17 字节码，包含显式 `EmptyTexture`，未混入专服探针或测试替身。

复现工具位于 `tools/ui-server/`。本地日志位于忽略目录 `build/diagnostics/issue144/`，专服报告为 `build/ui-server-run/ui-report.json`。

本轮没有进行真实客户端网络往返、界面外观或 GUI 流体桶交互验收。FakePlayer 的 factory 调用不等于真实玩家收包。KubeJS/Rhino 对 LDLib 自身客户端控件的反射警告另行保留，不将其计作本工程公共菜单初始化失败，也没有修改 LDLib JAR。
