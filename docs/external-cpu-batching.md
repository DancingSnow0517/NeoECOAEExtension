# 外部合成 CPU 与 ECO 快速批量合成

## 支持范围

- 原版 AE2 合成 CPU：基础 Mixin 接入，不需要安装 OmniCell。
- OmniCell 量子处理器：其协处理器加速使用 AE2 的 CraftingCpuLogic，因此直接复用原版入口，不再重复注入独立的 OmniCpu 执行器。
- AdvancedAE 量子计算机：AdvCraftingCPULogic 接入相同的批量执行器，保留自己的任务、CPU 生命周期及产物路由。

不需要修改这三个上游模组。AdvancedAE 入口只在安装 AdvancedAE 时加载。安装 Thunderbolt 时，其外层批量循环对未实现 Thunderbolt 批量接口的 ECO Provider 回退至原生执行方法，随后仍由 ECO 批量入口处理，不能仅因安装 Thunderbolt 而跳过适配。安装 Molecular Manipulator（OmniSequence）时，AE2 与 AdvancedAE 的入口一致让其负责提取和记账，使用已有的 ECO Provider 适配，避免混用两套执行上下文。

## 修复的关键

CPU 的推送额度与一次推送包含的合成次数分开计算。即便原版 CPU 本次只剩 1 个推送额度，也可以向具备 512 个可用槽位的 FX 工作核心提交 512 次合成；成功之后消耗 1 个推送额度，并从任务中扣除实际接受的 512 次。

512 表示配方执行次数，未必等于产出物品数量。例如每次产出 4 个物品的配方，512 次对应 2048 个产物。批次始终由任务剩余次数、CPU 实际材料、供电、配方验证结果以及工作核心当前容量共同限制，并非强制填入 512。剩余任务或材料不足时会缩小批次；不具备已验证批量能力的 Provider 保留正常单次发配。

## 资源与任务结算

ECOExternalCpuFastPath 使用统一的 ECOFastPathFacade：先在库存副本上解析单次输入，再在 CPU 真实库存中执行材料与能量事务。成功后按返回的实际总量登记产物、容器余料及进度，不重复提取单次材料。

- Provider 明确拒收或按协议抛出可回滚异常：恢复材料及能量，不扣任务。
- 网络暂时无法接收的能量退款：保留在 CPU 的 neoecoaeFastPath 存档字段，重载后继续退款，空闲 CPU 也会尝试退还。
- 接收状态不确定或接收后的记账异常：暂停任务，并阻止同一次调用继续走原版发配，避免重复生产或凭空退款。此类异常需要检查日志及任务实际状态，不能假定已自动修复。
- 发配携带合成任务 UUID；产物继续按任务回收。单次回退也携带 UUID，完成任务时释放工作核心上对应任务的余料。

普通 NATIVE 合同的 ECO 计划可以交给已适配的外部 CPU。需要 ECO 阶段调度、循环顺序或任意精度账本的计划仍要求 ECO CPU；不能仅为了允许选择外部 CPU 而丢掉执行约束。两个 CPU 的 trySubmitJob 入口也会验证这一点，覆盖显式选定 CPU、绕过自动选择的提交方式。

## 自动化验证

运行 ./gradlew.bat test --tests '*ECOExternalCpu*Test'。

- 三种 CPU 的任务适配：一个推送额度接受 512 次；连续批次任务归零，输入、产物与余料精确计数。
- 材料上限、忙碌 Provider、零推送额度、待收数量溢出以及模拟供电后实际断电。
- 拒收、可回滚异常、无法确认接收、接收后记账失败，以及能量退款存档往返。
- 原生计划允许提交，阶段/循环/大订单计划拒绝外部执行，显式 CPU 提交入口不能绕过检查。
- 对当前依赖 JAR 检查两种 CPU 的注入方法、任务字段及时间统计调用签名。
- 两种 CPU 的实际注入处理方法分别覆盖无额外引擎、仅 Thunderbolt、仅 OmniSequence、两者共存；验证 Thunderbolt 回退仍进入 ECO，OmniSequence 保留其记账所有权。

这些测试验证调度与适配契约；未替代实际游戏内的 Mixin 加载和多方块验收。

## 游戏内验收步骤

1. 搭建 ECO 样板总线及 FX 工作核心，提供足够材料、电力和对应冷却条件，确认核心具有 512 个可用批量槽位。
2. 分别仅启用原版 AE2 CPU、OmniCell 量子处理器、AdvancedAE 量子计算机。每次在确认界面选定对应 CPU，提交至少 1024 次普通工作台配方任务。
3. 原版 CPU 不安装额外协处理器也应提交满容量批次；对照 FX 实际投料，确认不是只投入 1 次。任务总计、最终产物及容器余料应与配方一致。
4. 分别测试材料只够较小批次、工作核心忙碌、供电不足、合成中保存重载及取消。确认没有负数任务、重复产物或材料丢失。
5. 启用 AdvancedAE 与 OmniCell 的整合环境时再次测试；有接管 AE2 循环的其他模组时，单独验证其 Provider 适配路径。
