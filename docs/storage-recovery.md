# 存储保存与恢复

普通盘按 UUID 保存到世界的 `data/neoecoae_cells/`；无限域保存到
`data/neoecoae_infinite/`。物品 NBT 主要保存身份和摘要，单独复制矩阵物品不能代替库存备份。

## 保存保证

- 普通盘和无限域均先写临时文件、刷盘并回读校验，再原子替换正式文件。
- 普通盘的显式保存只提交该盘。自动保存仍由 Minecraft SavedData 生命周期管理。
- 无限域每五秒最多发起一次后台检查点，后台只使用冻结的 NBT；AEKey 与世界对象操作留在服务器线程。
- 世界强制保存、停服、关键转移会等待写入完成。冷加载的磁盘读取和解压在后台进行。
- 存取后数量完全回到已提交基础值、且回执等元数据未变化时，跳过冗余写盘；在线版本号仍更新以使缓存和转移计划失效。已提交过的数量增量必须先持久化撤销，不能直接跳过。
- 保存失败隔离受影响的盘或域。普通盘保留坏条目，允许取出健康资源，但在未解析条目解决前禁止新增写入和整盘迁移。
- 无限转普通通过 `data/neoecoae_transfers/` 的恢复日志提交目标库存和源清空结果。目标计划不提前修改在线库存；启动时在加载世界前完成未结束的提交。

这些机制保护已提交数据，不能保证尚未保存的操作在进程崩溃后仍然存在，也不能让玩家背包、所有模组和区块保存成为同一个事务。

## 诊断和恢复

先停止自动化存取并保存完整世界备份，保留日志中的 UUID。以下命令需要管理员权限。

```text
/neoecoae storage diagnose <域UUID>
/neoecoae storage recover <域UUID>
/neoecoae storage recover-cell <普通盘UUID>
```

`recover` 重试读取，或在临时磁盘故障解除后重试提交仍在内存中的库存；不会主动回滚数量。
如果存在未完成的跨文件转移，先修复磁盘访问，再重启以完成日志恢复。
已确认转移目标但无法写入时仅锁定该转移涉及的库存；日志本身无法辨认时会阻止启动，避免将半完成的转移公开给玩家。

普通盘和无限域会保留上一代 `.previous` 文件。无限域还使用 `.commit` 记录已提交版本，检测增量丢失。
需要历史恢复时明确执行：

```text
/neoecoae storage restore-previous <域UUID> confirm-rollback
/neoecoae storage restore-cell-previous <普通盘UUID> confirm-rollback
```

历史恢复可能回滚存入和取出的数量，导致与其他容器不一致。命令会先保留原文件作为 `.recovery-…` 证据。
无限域从兼容的基础和增量历史中选择可读组合。历史副本不是独立的异地备份，也不保证硬盘损坏后可恢复。

不要通过删除 `.delta.dat`、`.commit`、转移日志或修改物品 UUID 来解除锁定。
备份和还原应使用停服后的完整世界，或覆盖整个世界的同一时点文件系统快照；不要混用不同日期的区块、玩家和库存文件。

## 验证

`gradlew check` 包含序列化失败、局部坏记录、重复恢复、独立 JVM 强制退出、后台保存期间继续存取等测试。
真实 Forge 验收使用独立的 `run/storage-performance` 世界：

```text
gradlew -PstorageAcceptance verifyStoragePerformance
```

该验收使用真实 AE2 物品/流体键及存储接口，并不是完整大型 AE 网络的 TPS 承诺。

本次稳定性验证：JUnit 257 项通过、10 项环境相关测试跳过；独立 Forge 服务器的 4 项 GameTest 通过。
覆盖进程强制退出后日志重放、反复恢复时保留最新内存数量、真实物品重载、坏条目隔离、
跨文件转移、拒收数量反馈及满盘嵌套保护。验证世界与玩家存档隔离。
