# 大型集成工作站设计

本文档是大型集成工作站（`ECOLargeIntegratedWorkingStation`）升级卡、温度模式与 UI 的设计依据。温控数值集中在 `LargeWorkstationThermal` 中，作为初始值供实测调整。第 3、4 节温控规则已落实；升级卡门控与 UI 草稿整体改版仍为后续设计。

## 1. 决策总表

| 议题 | 决定 |
|---|---|
| 无卡时 | 只运行大型集成工作站的 ECO 原生配方 |
| 有卡时 | 只运行该卡对应模组的配方，ECO 原生配方不可用 |
| 卡的作用 | 只决定可用配方集，不影响并行、能耗、热量 |
| 拔卡 | 立即锁定，运行中批次按停机处理（保留进度与输入）；放回原卡后接着运行 |
| 超频 | 选择最大档位，温度持续达标才可运行该档批次；超频与主动冷却独立控制 |
| 冷却与温度 | 温度越高产热越快；低温使用高级冷却液可以净降温，不以恒温平衡为目标 |
| 常规并行 / 能耗 | 常规 256 并行，全部档位每份配方耗能均为 1× |
| 过热恢复 | 100% 锁定加工，连续实际消耗凛冰溶液 15 秒后回到 0% |
| 配置项 `largeWorkstationCompatRecipesEnabled` | 新机制上线后删除，由升级卡门控取代 |

## 2. 升级卡与配方门控

### 2.1 结构

- 单个升级槽，只接受升级卡物品（物品 tag 过滤）。
- 使用独立的 `AppEngInternalInventory(1)`，不接入 AE2 的 `UpgradeInventory`，因为大型机本身没有 AE2 升级槽。

### 2.2 可用配方集

| 卡状态 | 可用配方 |
|---|---|
| 无卡 | 仅 ECO 原生集成工作站配方 |
| 插入卡 X | 仅卡 X 对应模组的配方 |

ECO 原生配方在有卡时不可用。

### 2.3 批次规则

- 批次只在其配方属于当前可用配方集时运行。
- 卡变化导致某个批次不再被允许时，该批次进入停机状态：
  - 保留进度与已占用的输入。
  - 不产出、不退还，不丢失。
  - 状态显示"缺少 X 升级卡，已停机，请插回"，并向玩家发送一条提示。
- 放回原卡后，停机批次继续运行。
- 放回的是另一张卡时，只有该批次的配方属于新卡的集合才恢复运行；否则保持停机，提示所需卡。
- 插卡时正在运行的原生批次同样停机，规则对称。

### 2.4 卡与配方映射

全部联动配方分为三张卡：闪电卡、水晶卡、联动卡。

| 卡 | 配方类型 | 所属模组 | 备注 |
|---|---|---|---|
| 闪电卡 | `ae2lt:overload_processing`、`ae2lt:lightning_assembly`、`ae2lt:lightning_simulation` | AE2 Lightning Tech | |
| 水晶卡 | `ae2cs:circuit_etcher_recipe`、`ae2cs:crystal_aggregator_recipe` | ae2cs | 不含 EAE 晶体组装机 |
| 联动卡 | `advanced_ae:reaction`、`appgen:synthesizing`、`extendedae:crystal_assembler`、`extendedae_plus:crystal_assembler_plus` | Advanced AE、appgen、ExtendedAE / ExtendedAE Plus | 合并其余全部联动；`extendedae` 类仅在 `extendedae_plus` 加载时启用 |

映射由 `LargeWorkstationRecipes.getAll` 按卡的集合过滤，卡 ID 与配方类型集合一一对应。

### 2.5 配方浏览器

- 配方浏览器（JEI/EMI）显示全部兼容配方，并标注所需卡。
- 运行时门控以卡为准。

## 3. 超频与温度模式

高并行必须持续满足对应温度门槛，不能只在接单时检查一次。

| 档位 | 工作温度门槛 | 并行上限 | 每份配方能耗 |
|---|---|---|---|
| 常规 | 无要求 | 256 | 1× |
| 2 | ≥20% | 16,384 | 1× |
| 6 | ≥50% | 65,536 | 1× |
| 9 | ≥80% | 262,144 | 1× |

- **最大档位**：2 / 6 / 9 循环选择。超频开启时，新批次使用已满足温度门槛且不超过所选上限的最高档位；未达 20% 时为常规。
- **超频开关**：允许新批次采用高档位。关闭后已接收的超频批次暂停，常规批次仍可按队列执行。
- **主动冷却**：独立控制。液体只决定散热强度，不再直接门控可用档位；关闭冷却不会直接取消温度已经达标的高并行。
- **独立预热**：开启时启用超频并关闭主动冷却；主动冷却开启时停止预热。达到所选档位门槛后自动结束，温度下降不会自动补热。
- 批次创建时固定档位。温度跌破其门槛时暂停，保留输入与进度，重新达到门槛后继续。切换档位不会改写已经接收的批次。
- 加工能耗始终为 `基础配方耗能 × 基础配方次数`。高并行增加实际工作量，因此总耗电仍会增加；预热用电另行支付。
- 超过档位门槛不增加额外收益，不另行叠加温度配方加速。

## 4. 温度模型

### 4.1 状态与产热

- 温度 T 范围 0%–100%，内部 double 保留小数，GUI 显示两位小数；保存温度和过热锁定。
- 独立服务端方块 ticker 每 tick 结算冷却及预热。加工暂停、空闲或 AE2 调低加工回调频率时，冷却仍然有效。区块未加载时不结算，不补算离线时间。
- 常规加工不产热，本轮不叠加被动散热。

```text
满载加工产热（百分点/秒）= 0.2 + 0.8 × (T / 100)²
实际加工产热 = 满载加工产热 × 实际工作负载
温度变化 = 实际加工产热 + 实际付费电预热 − 成功消耗冷却液移除的热量
```

实际工作量按推进的基础配方次数相对该档满批工作量折算，包含倍率样板展开的基础操作数。分拆批次不会免除对应工作量的产热。缺电未推进、缺料、输出受阻、低温或过热暂停时不产加工热。

### 4.2 电预热

- 初始速度 2 个百分点/秒，完整预热功率 1,000 AE/t。
- 供电不足按实际支付比例升温；最后不足一个 tick 的升温只收取对应比例能量。
- 达到所选档位温度后自动停止，不自动重新启动。玩家需减少或关闭冷却后主动预热。
- 过热锁定时不能启动预热。

### 4.3 主动冷却

参考流量为 **100 mB/服务端 tick（2,000 mB/s）**，与加工回调频率无关。

| 冷却液 | 每秒移除温度（百分点） |
|---|---|
| 水 | 0.1 |
| 钠 | 0.3 |
| 凛冰溶液 | 0.6 |

满载、关闭预热时的参考值：

| 温度 | 产热 /s | 水净变化 /s | 钠净变化 /s | 凛冰净变化 /s |
|---|---|---|---|---|
| 20% | +0.232 | +0.132 | −0.068 | −0.368 |
| 50% | +0.400 | +0.300 | +0.100 | −0.200 |
| 80% | +0.712 | +0.612 | +0.412 | +0.112 |

- 净变化允许为负，最终温度限制在 0%–100%。低温使用高级液体会真正降温，可能跌破高并行门槛。
- 不要求存在长期产热/散热平衡点，不以自动补热抵消过强冷却。
- 暂停、空闲时温度大于 0 且主动冷却开启，仍可消耗液体降温；到 0 后停止消耗。
- 副产物按原冷却配方比例生成，保留分数余量。先确认输出容量，液体扣除与副产物输出均成功才获得冷却效果。
- 缺液、无匹配配方、输出堵塞时不计冷却，不扣除无法处理的冷却液交易。

### 4.4 100% 过热锁定

- 达到 100% 立即锁定加工及新接单，关闭预热，保留输入和进度，不损坏机器或材料。
- 只能用**凛冰溶液本体**解除锁定，自定义 tier 9 的其他液体也不能替代。
- 主动冷却必须连续成功消耗凛冰溶液 **300 tick（15 秒）**。参考流量下共消耗 **30,000 mB（30 B）**。
- 强制恢复采用专用曲线，从 100% 降至 0%，不使用正常 −0.6/s 的速度。直到完整 300 tick 结束才解除锁定。
- 关闭冷却、缺液、输出堵塞或结构解体时中断，进度归零并恢复 100%。重载保留过热锁定，重新开始连续计时。
- 切换档位、开关超频或单纯等待不能解除锁定。恢复到 0% 后需手动重新预热。

### 4.5 旧批次兼容

- 已保存的有效 8× / 32× / 64× 超频批次按 1× 支付剩余加工，保留输入、输出、闪电提取记录和进度。
- 旧常规批次最多 1,024 次的已接收输入继续保留，新接单上限改为 256，不因降上限丢弃旧批次。
- 无温度字段的旧存档从 0% 开始，旧超频批次需手动预热后继续。

## 5. UI

依据 `UI` 需求图：

**物品栏区域**
- 物品栏：玩家背包三排九格；批次材料由内部账本保管。
- 物品快捷栏：玩家快捷栏。

**功能显示区域**
- 温度条：显示百分比，标出 20% / 50% / 80% 门槛；100% 过热锁定，显示凛冰恢复秒数。
- 独立预热按钮、最大档位选择、超频与主动冷却开关。
- 冷却液槽位。
- 冷却输出液槽位。
- 升级卡槽（建议放在此区域，位置待确认）。

**总信息显示区域**
- 网络连接与工作状态：正常 / 缺卡停机 / 过热 / 缺冷却液 / 缺能 等。
- 耗能情况。
- 并行情况：当前有效档位、选择档位、并行上限。
- 温度情况：百分比、低温暂停原因、过热锁定和连续凛冰恢复秒数。
- 已安装的兼容模块：卡名或"无"。

**实际合成工作列表**
- 每个批次为一张卡片。
- 左侧槽位显示产物物品。
- 右侧三行：物品名称；合成进度与数量；耗能。

## 6. 配置项移除

`largeWorkstationCompatRecipesEnabled` 在新机制上线后删除，涉及：

- `NEConfig`：字段、`ModConfigSpec` 定义、静态赋值。
- `ConfigLangs` 与 `src/main/resources/assets/neoecoae/lang/` 下各语言文件中的对应键（zh_cn、en_us、zh_hk、zh_tw、lzh、en_ud，其中 en_ud 与 en_us 为生成文件）。
- `LargeWorkstationRecipeTest` 中的引用。

`LargeWorkstationRecipes.getAll` 的缓存键需要加入卡状态，否则卡变化不会刷新缓存。

## 7. 实现触点

- `recipe/LargeWorkstationRecipes`：按卡过滤配方集，删除配置读取。
- `blocks/entity/LargeWorkstationOverclock`：256 基础并行、20% / 50% / 80% 温度门槛、全档 1× 耗能与旧档位迁移。
- `blocks/entity/ECOLargeIntegratedWorkingStationBlockEntity`：
  - 后续：升级槽与卡变化回调（停机 / 恢复）。
  - 温度状态、独立服务端每 tick 结算与手动预热。
  - 有效档位计算（`getCurrentBatchProfile`）。
  - 本轮暂停原因：`TEMPERATURE_LOW`、`OVERHEATED`；`CARD_LOCKED` 随卡门控后续接入。
- `blocks/entity/LargeWorkstationThermal`：产热、净降温、预热和 15 秒连续恢复状态转移，独立单元测试。
- 后续新增第 2.4 节明确的 3 种升级卡：物品、合成配方、语言、贴图。
- 当前 GUI 增加温度条、恢复进度、预热和选档按钮；草稿整体布局与升级卡槽为后续工作。
