# 大型集成工作站设计

本文档是大型集成工作站（`ECOLargeIntegratedWorkingStation`）升级卡、温度模式与 UI 的设计依据。数值为初始值，实现时放在常量中，靠实测调整。

## 1. 决策总表

| 议题 | 决定 |
|---|---|
| 无卡时 | 只运行大型集成工作站的 ECO 原生配方 |
| 有卡时 | 只运行该卡对应模组的配方，ECO 原生配方不可用 |
| 卡的作用 | 只决定可用配方集，不影响并行、能耗、热量 |
| 拔卡 | 立即锁定，运行中批次按停机处理（保留进度与输入）；放回原卡后接着运行 |
| 超频 | 必须开启主动冷却并有冷却液。超频开启即进入温度模式，并通过选择最大并行档位来设定并行数 |
| 冷却与持续时间 | 冷却液等级越高，超频持续时间越长 |
| 配置项 `largeWorkstationCompatRecipesEnabled` | 新机制上线后删除，由升级卡门控取代 |

## 2. 升级卡与配方门控

### 2.1 结构

- 单个升级槽，只接受升级卡物品（物品 tag 过滤）。
- 使用独立的 `AppEngInternalInventory(1)`，不接入 AE2 的 `UpgradeInventory`，因为大型机本身没有 AE2 升级槽。

### 2.2 可用配方集

| 卡状态 | 可用配方 |
|---|---|
| 无卡 | 仅 ECO 原生集成工作站配方 |
| 插入卡 X | 仅卡 X 对应模组的配方 |

ECO 原生配方在有卡时不可用。

### 2.3 批次规则

- 批次只在其配方属于当前可用配方集时运行。
- 卡变化导致某个批次不再被允许时，该批次进入停机状态：
  - 保留进度与已占用的输入。
  - 不产出、不退还，不丢失。
  - 状态显示"缺少 X 升级卡，已停机，请插回"，并向玩家发送一条提示。
- 放回原卡后，停机批次继续运行。
- 放回的是另一张卡时，只有该批次的配方属于新卡的集合才恢复运行；否则保持停机，提示所需卡。
- 插卡时正在运行的原生批次同样停机，规则对称。

### 2.4 卡与配方映射

全部联动配方分为三张卡：闪电卡、水晶卡、联动卡。

| 卡 | 配方类型 | 所属模组 | 备注 |
|---|---|---|---|
| 闪电卡 | `ae2lt:overload_processing`、`ae2lt:lightning_assembly`、`ae2lt:lightning_simulation` | AE2 Lightning Tech | |
| 水晶卡 | `ae2cs:circuit_etcher_recipe`、`ae2cs:crystal_aggregator_recipe` | ae2cs | 不含 EAE 晶体组装机 |
| 联动卡 | `advanced_ae:reaction`、`appgen:synthesizing`、`extendedae:crystal_assembler`、`extendedae_plus:crystal_assembler_plus` | Advanced AE、appgen、ExtendedAE / ExtendedAE Plus | 合并其余全部联动；`extendedae` 类仅在 `extendedae_plus` 加载时启用 |

映射由 `LargeWorkstationRecipes.getAll` 按卡的集合过滤，卡 ID 与配方类型集合一一对应。

### 2.5 配方浏览器

- 配方浏览器（JEI/EMI）显示全部兼容配方，并标注所需卡。
- 运行时门控以卡为准。

## 3. 超频与温度模式

- **超频开关**即温度模式开关：开启后热量开始累积，并允许选择超频并行档位。
- **主动冷却开关**：超频的前提。关闭时超频不可开启，状态显示"需要开启主动冷却"。
- **最大并行档位**：常规 / 2 / 6 / 9，选择上限由冷却液等级决定。

| 档位 | 所需冷却液 | 能耗倍率 | 并行上限 |
|---|---|---|---|
| 常规 | 无 | 1× | 1,024 |
| 2 | 水（tier 2） | 8× | 16,384 |
| 6 | 钠（tier 6） | 32× | 65,536 |
| 9 | 凛冰溶液（tier 9） | 64× | 262,144 |

有效档位：

```
有效档位 = min(选择的档位, 冷却液等级, 热量限制档位)
```

- 超频关闭时，有效档位为常规，不产热。
- 热量限制档位只作用于新批次；运行中批次保持其档位（能耗倍率与并行上限在批次创建时已固定）。

## 4. 热量模型

### 4.1 状态与结算

- 状态：热量 `H`，范围 0–100%，内部以 0.01% 为单位存整数（10000 = 100%）。
- 持久化，并同步到 GUI。
- 每 20 个服务端 tick（1 秒）结算一次。

```
ΔH/秒 = 产热（仅超频批次运行时）
       − 被动散热（运行中 0.10 / 空闲 1.00）
       − 主动冷却移除（仅超频批次运行且主动冷却开启时）
```

- "运行中"指本秒内有批次实际推进。缺能、缺料、停机时视为空闲。
- 常规运行不产热。

### 4.2 超频档位的热数值

| 档位 | 产热 %/s | 冷却液 | 冷却移除 %/s | 净升温 %/s | 连续运行至过热（从 0%） |
|---|---|---|---|---|---|
| 2 | 2.0 | 水 | 1.0 | 0.9 | ≈ 111 秒 |
| 6 | 6.0 | 钠 | 5.5 | 0.4 | ≈ 250 秒 |
| 9 | 12.0 | 凛冰溶液 | 11.7 | 0.2 | ≈ 500 秒 |

净升温 = 产热 − 冷却移除 − 运行被动散热（0.10）。

**持续时间原则**：冷却液等级越高，冷却移除越大，净升温越小，连续超频的持续时间越长。冷却液与超频档位是独立组合：用凛冰运行 2 档，净升温为负，可长期运行。

**无冷却时**（只有被动散热，仅作参考）：2 档约 53 秒，6 档约 17 秒，9 档约 8 秒过热。这说明主动冷却是超频的必要条件。

### 4.3 热量限制与滞回

| 热量区间 | 限制 | 进入条件 | 退出条件 |
|---|---|---|---|
| 0%–59% | 无 | — | — |
| 60%–84% | 最高 2 档 | ≥ 60% | < 50% |
| 85%–99% | 仅常规 | ≥ 85% | < 75% |
| 100% | 过热停机 | ≥ 100% | ≤ 40% 恢复 |

退出阈值低于进入阈值，避免档位在临界值附近来回跳动。

### 4.4 过热

- 热量达到 100% 时，所有运行中批次暂停，状态显示"过热"。
- 冷却至 40% 后恢复，批次保持原档位续算。
- 空闲时被动散热为 1%/s，从 100% 降至 40% 约需 60 秒。

## 5. UI

依据 `UI` 需求图：

**物品栏区域**
- 物品栏：机器输入/输出物品槽。
- 物品快捷栏：玩家快捷栏。

**功能显示区域**
- 温度条：分段着色（0–59 绿、60–84 黄、85–99 橙、100 红闪），并标出 60 / 85 / 100 分界。
- 冷却液槽位。
- 冷却输出液槽位。
- 升级卡槽（建议放在此区域，位置待确认）。

**总信息显示区域**
- 网络连接与工作状态：正常 / 缺卡停机 / 过热 / 缺冷却液 / 缺能 等。
- 耗能情况。
- 并行情况：当前有效档位、选择档位、并行上限。
- 温度情况：热量百分比、限制原因、按当前负载预计剩余秒数。
- 已安装的兼容模块：卡名或"无"。

**实际合成工作列表**
- 每个批次为一张卡片。
- 左侧槽位显示产物物品。
- 右侧三行：物品名称；合成进度与数量；耗能。

## 6. 配置项移除

`largeWorkstationCompatRecipesEnabled` 在新机制上线后删除，涉及：

- `NEConfig`：字段、`ModConfigSpec` 定义、静态赋值。
- `ConfigLangs` 与 `src/main/resources/assets/neoecoae/lang/` 下各语言文件中的对应键（zh_cn、en_us、zh_hk、zh_tw、lzh、en_ud，其中 en_ud 与 en_us 为生成文件）。
- `LargeWorkstationRecipeTest` 中的引用。

`LargeWorkstationRecipes.getAll` 的缓存键需要加入卡状态，否则卡变化不会刷新缓存。

## 7. 实现触点

- `recipe/LargeWorkstationRecipes`：按卡过滤配方集，删除配置读取。
- `blocks/entity/LargeWorkstationOverclock`：增加每档产热与冷却移除（按冷却等级查表）。
- `blocks/entity/ECOLargeIntegratedWorkingStationBlockEntity`：
  - 升级槽与卡变化回调（停机 / 恢复）。
  - 热量状态与每秒结算。
  - 有效档位计算（`getCurrentBatchProfile`）。
  - 新暂停原因：`CARD_LOCKED`、`OVERHEATED`。
- 热量计算抽成纯静态方法（如 `LargeWorkstationThermal.step(...)`），便于单元测试。
- 新增 4 种（或按 2.4 结论确定的数量）升级卡：物品、合成配方、语言、贴图。
- GUI：按第 5 节重新布局。
