# 大型集成工作站设计

本文档是大型集成工作站（`ECOLargeIntegratedWorkingStation`）兼容模块、温度模式与 UI 的设计依据。兼容模块是方块，安装在集成工作站控制器后方，替换原结构中的一个机壳；完整结构仍为 12 个方块。数值为初始值，实现时放在常量中，靠实测调整。

## 1. 决策总表

| 议题 | 决定 |
|---|---|
| 模块形态与安装位置 | 模块为方块，替换控制器后方的机壳；只允许一个安装位，总方块数仍为 12 |
| 未安装模块时 | 安装位保留机壳，只运行大型集成工作站的 ECO 原生配方 |
| 安装模块时 | 只运行该模块对应的配方，ECO 原生配方不可用 |
| 模块的作用 | 只决定可用配方集，不影响并行、能耗、热量 |
| 拆除或更换模块 | 立即停止不再允许的批次，保留进度与输入；恢复所需模块并重新成型后继续运行 |
| 超频 | 必须开启主动冷却并有冷却液。超频开启即进入温度模式，并通过选择最大并行档位来设定并行数 |
| 冷却与持续时间 | 冷却液等级越高，超频持续时间越长 |
| 配置项 `largeWorkstationCompatRecipesEnabled` | 新机制上线后删除，由模块门控取代 |

## 2. 模块方块与配方门控

### 2.1 结构

- 保留原来的 3 × 2 × 2、共 12 方块结构，只将控制器后方中间的机壳位置改为可选模块位。
- 按 `NEMultiBlocks.createLargeIntegratedWorkingStation()` 的局部坐标，控制器位于 `(1, 1, 0)`，模块位位于 `(1, 1, 1)`。两者在同一层，模块紧邻控制器后方；不是控制器上方，也不额外增加第 13 个方块。
- 模块位允许放置原机壳或三种受支持模块中的任意一种。机壳表示未安装模块，模块方块表示启用对应配方集；其他位置放置模块不生效。
- 模块位是基础结构的一部分。模块位为空或放置其他方块时，结构不完整，机器不能运行；放回机壳或有效模块后可重新成型。
- 模块保持可见和可拆换，不应用机壳的成型隐藏效果。旋转机器时，模块位随结构朝向变换，“后方”始终相对于控制器朝向。
- 模块以方块及其对应方块物品注册，通过方块 ID 或模块类型映射识别。GUI 不设模块物品槽，控制器不新增升级物品库存。

上层结构示意（局部坐标 `y = 1`，正面为 `z = 0`）：

```text
             x = 0       x = 1          x = 2
前方 z = 0   机壳        控制器         机壳
后方 z = 1   机壳        机壳 / 模块    机壳
```

下层 6 个方块保持原布局，整体仍为 12 个方块。

### 2.2 可用配方集

| 模块位状态 | 可用配方 |
|---|---|
| 原机壳（未安装模块） | 仅 ECO 原生集成工作站配方 |
| 模块 X | 仅模块 X 对应的配方 |
| 空位或其他方块 | 结构不完整，不运行任何配方 |

ECO 原生配方在安装模块时不可用。模块的配方类型集合可覆盖一个或多个模组，详见第 2.4 节。

### 2.3 批次规则

- 批次只在结构完整且其配方属于当前可用配方集时运行。新批次的匹配、接单与执行均使用同一模块状态。
- 模块拆除、更换或换回机壳导致某个批次不再被允许时，该批次进入停机状态：
  - 保留进度与已占用的输入。
  - 不产出、不退还，不丢失。
  - 联动批次显示“需要 X 模块，已停机，请安装到控制器后方”，原生批次显示“需要原机壳，已停机，请替换控制器后方的模块”。状态变化时向玩家发送一条提示，避免每 tick 重复发送。
- 模块位被挖空时，所有批次先因结构不完整暂停。保留控制器内的批次、进度、输入归属及热量，不能因模块位拆换或重新成型而清空；本规则以控制器未被拆除为前提。
- 放回原模块并重新成型后，允许的停机批次继续运行。
- 换成另一种模块时，只有批次配方属于新模块的集合才恢复运行；否则保持停机，显示所需模块。
- 原生批次在机壳被替换为模块后同样停机；将模块换回机壳并重新成型后恢复，规则对称。
- 存档加载或区块重新加载后，从模块位的实际方块重新解析模块状态；结构及模块状态核对完成前，不推进或接收批次。

### 2.4 模块与配方映射

全部联动配方分为三种模块方块：闪电模块、水晶模块、联动模块。一个安装位一次只能启用一种模块。

| 模块方块 | 配方类型 | 所属模组 | 备注 |
|---|---|---|---|
| 闪电模块 | `ae2lt:overload_processing`、`ae2lt:lightning_assembly`、`ae2lt:lightning_simulation` | AE2 Lightning Tech | |
| 水晶模块 | `ae2cs:circuit_etcher_recipe`、`ae2cs:crystal_aggregator_recipe` | ae2cs | 不含 EAE 晶体组装机 |
| 联动模块 | `advanced_ae:reaction`、`appgen:synthesizing`、`extendedae:crystal_assembler`、`extendedae_plus:crystal_assembler_plus` | Advanced AE、appgen、ExtendedAE / ExtendedAE Plus | 合并其余全部联动；`extendedae` 类仅在 `extendedae_plus` 加载时启用 |

模块类型与配方类型集合一一对应。由控制器解析模块位，再向 `LargeWorkstationRecipes` 的运行时筛选入口传递模块类型，按对应集合过滤；不要将某台机器的模块状态写入全局配置或配方管理器的共享状态。

### 2.5 配方浏览器

- 配方浏览器（JEI/EMI）显示当前已加载模组的全部受支持配方，并标注所需模块名称、模块方块图标和“安装于控制器后方”。原生配方标注“模块位保留机壳”。
- 浏览器配方目录不依赖某台机器当前安装的模块；运行时门控以该机器模块位的实际方块为准。

## 3. 超频与温度模式

- **超频开关**即温度模式开关：开启后热量开始累积，并允许选择超频并行档位。
- **主动冷却开关**：超频的前提。关闭时超频不可开启，状态显示"需要开启主动冷却"。
- **最大并行档位**：常规 / 2 / 6 / 9，选择上限由冷却液等级决定。

| 档位 | 所需冷却液 | 能耗倍率 | 并行上限 |
|---|---|---|---|
| 常规 | 无 | 1× | 1,024 |
| 2 | 水（tier 2） | 8× | 16,384 |
| 6 | 钠（tier 6） | 32× | 65,536 |
| 9 | 凛冰溶液（tier 9） | 64× | 262,144 |

有效档位：

```
有效档位 = min(选择的档位, 冷却液等级, 热量限制档位)
```

- 超频关闭时，有效档位为常规，不产热。
- 热量限制档位只作用于新批次；运行中批次保持其档位（能耗倍率与并行上限在批次创建时已固定）。

## 4. 热量模型

### 4.1 状态与结算

- 状态：热量 `H`，范围 0–100%，内部以 0.01% 为单位存整数（10000 = 100%）。
- 持久化，并同步到 GUI。
- 每 20 个服务端 tick（1 秒）结算一次。

```
ΔH/秒 = 产热（仅超频批次运行时）
       − 被动散热（运行中 0.10 / 空闲 1.00）
       − 主动冷却移除（仅超频批次运行且主动冷却开启时）
```

- "运行中"指本秒内有批次实际推进。缺能、缺料、停机时视为空闲。
- 常规运行不产热。

### 4.2 超频档位的热数值

| 档位 | 产热 %/s | 冷却液 | 冷却移除 %/s | 净升温 %/s | 连续运行至过热（从 0%） |
|---|---|---|---|---|---|
| 2 | 2.0 | 水 | 1.0 | 0.9 | ≈ 111 秒 |
| 6 | 6.0 | 钠 | 5.5 | 0.4 | ≈ 250 秒 |
| 9 | 12.0 | 凛冰溶液 | 11.7 | 0.2 | ≈ 500 秒 |

净升温 = 产热 − 冷却移除 − 运行被动散热（0.10）。

**持续时间原则**：冷却液等级越高，冷却移除越大，净升温越小，连续超频的持续时间越长。冷却液与超频档位是独立组合：用凛冰运行 2 档，净升温为负，可长期运行。

**无冷却时**（只有被动散热，仅作参考）：2 档约 53 秒，6 档约 17 秒，9 档约 8 秒过热。这说明主动冷却是超频的必要条件。

### 4.3 热量限制与滞回

| 热量区间 | 限制 | 进入条件 | 退出条件 |
|---|---|---|---|
| 0%–59% | 无 | — | — |
| 60%–84% | 最高 2 档 | ≥ 60% | < 50% |
| 85%–99% | 仅常规 | ≥ 85% | < 75% |
| 100% | 过热停机 | ≥ 100% | ≤ 40% 恢复 |

退出阈值低于进入阈值，避免档位在临界值附近来回跳动。

### 4.4 过热

- 热量达到 100% 时，所有运行中批次暂停，状态显示"过热"。
- 冷却至 40% 后恢复，批次保持原档位续算。
- 空闲时被动散热为 1%/s，从 100% 降至 40% 约需 60 秒。

## 5. UI

依据 `UI` 需求图：

**物品栏区域**
- 物品栏：机器输入/输出物品槽。
- 物品快捷栏：玩家快捷栏。

**功能显示区域**
- 温度条：分段着色（0–59 绿、60–84 黄、85–99 橙、100 红闪），并标出 60 / 85 / 100 分界。
- 冷却液槽位。
- 冷却输出液槽位。
- 模块状态显示：模块方块图标、名称及安装位置提示。该区域只展示信息，模块通过世界中的方块安装与拆换。

**总信息显示区域**
- 网络连接与工作状态：正常 / 结构不完整 / 模块不匹配停机 / 过热 / 缺冷却液 / 缺能 等。
- 耗能情况。
- 并行情况：当前有效档位、选择档位、并行上限。
- 温度情况：热量百分比、限制原因、按当前负载预计剩余秒数。
- 已安装的兼容模块：模块名称或“未安装（原生配方）”；模块位为空或无效时显示“模块位结构不完整”，避免与原生模式混淆。

**实际合成工作列表**
- 每个批次为一张卡片。
- 左侧槽位显示产物物品。
- 右侧三行：物品名称；合成进度与数量；耗能。
- 暂停批次显示具体原因；模块不匹配时同时显示所需模块，原生批次提示换回机壳。

## 6. 配置项移除

`largeWorkstationCompatRecipesEnabled` 在新机制上线后删除，涉及：

- `NEConfig`：字段、`ModConfigSpec` 定义、静态赋值。
- `ConfigLangs` 与 `src/main/resources/assets/neoecoae/lang/` 下各语言文件中的对应键（zh_cn、en_us、zh_hk、zh_tw、lzh、en_ud，其中 en_ud 与 en_us 为生成文件）。
- `LargeWorkstationRecipeTest` 中的引用。

配方缓存分为完整目录与运行时筛选两层：

- 完整目录包含原生配方和已加载模组的受支持配方，供 JEI/EMI 展示和 `getById(...)` 恢复已保存批次；模块变化不能让原有配方 ID 失去可查询性。
- 运行时先按模块类型筛选，再在允许的集合内去重与匹配。不能先跨模块去重，否则其他模块下的低成本等价配方可能挤掉当前模块可用的配方。
- 若缓存筛选结果，缓存键包含模块类型及配方重载状态。模块位发生变化时，刷新控制器可用配方与通讯接口样板视图，并重新检查待执行批次；结构无效时禁止接单。
- 数据包重载后刷新两层缓存；每台机器独立筛选，避免不同模块工作站互相影响。

## 7. 实现触点

- `all/NEBlocks`、方块实现与数据生成：注册闪电、水晶、联动三种模块方块及对应方块物品、合成配方、掉落、模型、贴图、语言与创造标签页条目。
- `all/NEMultiBlocks` 与多方块匹配/成型逻辑：将 `(1, 1, 1)` 改为“原机壳或受支持模块”的可选方块位，保留其他 11 个位置；正确处理方向变换，并保持模块可见。自动搭建默认放置机壳，预先放置的有效模块应保留。
- `recipe/LargeWorkstationRecipes`：完整目录与按模块筛选入口分离，删除配置读取，保留原始配方 ID 查找；筛选后再进行集合内去重。
- `blocks/entity/LargeWorkstationOverclock`：增加每档产热与冷却移除（按冷却等级查表）。
- `blocks/entity/ECOLargeIntegratedWorkingStationBlockEntity`：
  - 解析控制器后方模块位，通过相邻方块更新、重新成型与存档加载刷新模块状态（停机 / 恢复）。
  - 将当前模块类型传入接单、配方匹配和批次推进校验；持久化批次及其配方来源，结构变化不清空输入与进度。
  - 热量状态与每秒结算。
  - 有效档位计算（`getCurrentBatchProfile`）。
  - 新暂停原因：`MODULE_LOCKED`、`OVERHEATED`；结构不完整单独显示，原生批次被模块阻止时也使用模块门控原因并提示换回机壳。
- `blocks/entity/LargeWorkstationPatternProvider` 与通讯接口：模块变化后刷新允许接收的样板与配方匹配结果，防止通过旧样板视图绕过门控。
- 热量计算抽成纯静态方法（如 `LargeWorkstationThermal.step(...)`），便于单元测试。
- GUI 与 JEI/EMI：按第 5 节布局模块状态显示，标注各配方的安装要求；更新各语言文件与数据生成入口。
- 游戏内指南与自动搭建预览：展示 12 方块结构中的模块替换位、三种模块用途及拆换后的停机恢复规则。

## 8. 待确认

1. 三种模块方块的最终外观、注册 ID 与合成材料；用途按第 2.4 节确定，名称暂定闪电模块、水晶模块、联动模块。
2. 模块状态显示在 GUI 中的具体布局；形态、世界安装位与总方块数已确定，不再作为待确认项。
3. 冷却液消耗量（现为每处理 tick 100 mB）是否随新热量模型调整，当前沿用原值。

## 9. 模块机制验收

- 无模块时，模块位为机壳，12 方块结构正常成型，仅接收原生配方。
- 三种模块分别替换控制器后方机壳后均可成型，只启用自身集合，原生配方不可用。
- 模块放在其他位置不启用；模块位为空或无效时不能成型。所有水平朝向均识别控制器后方的正确位置。
- 运行中拆除、更换模块或换回机壳，受影响批次停机且保留进度与输入；恢复所需结构后继续，无重复消耗或重复产出。
- 暂停后保存并重载，仍按实际模块位正确恢复；模块变化及配方重载会同步更新通讯接口与 GUI。
- 不同模块的工作站同时运行时互不影响；模块门控不改变原定的并行、能耗与热量数值。
- JEI/EMI 能浏览完整受支持目录并显示安装要求；跨模块等价配方不会使当前模块的可用配方消失。
