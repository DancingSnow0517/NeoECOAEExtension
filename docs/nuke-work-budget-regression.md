# 氢氧联合产出整数规划预算回归

现场日志在 2026-10-09 20:01:25 报告 `nuke ×1001` 的 `WORK_LIMIT`：组件规划累计 5,000,001 次检查点，约 7 秒，未到 10 秒时间上限。debug 日志显示组件 179（氘/氚）、17（石化）及 7（原油）已完成，组件 10（氢/氧）进入求解后没有返回。`nuke ×1` 的该组件由库存直接满足，没有触发整数求解。

从存档中的样板组装库存读到两张真实加工样板：

| 样板入口 | 输入 | 全部输出 |
| --- | --- | --- |
| 氧气 | 水 3,000 | 氧气 1,000，氢气 2,000 |
| 氢气 | 水 3,000 | 氢气 2,000，氧气 1,000 |

二者是不同的物理样板，保留各自身份和原入口；本次没有合并或删除玩家样板。它们的材料方程相同，但整数求解器原先仅用分数形式的线性松弛目标剪枝。若线性松弛的最少执行次数为 `10,682.75`，已找到 `10,683` 次的整数解后，仍认为分数下界小于现有解，继续枚举两张样板之间的大量等价分配。

修复将分支下界改为 `ceil(线性松弛执行次数总和)`。因为每张物理样板的执行次数都是非负整数，总次数也必为整数；下界向上取整是严格有效的剪枝，仍保留整数最优性、精确大整数计算以及后续执行顺序与真实供给验证。没有增大预算，也没有把未知结果当作缺料。

回归使用现场记录的目标 `氢气 27,615,000 / 氧气 1,503,000` 与读取时存档库存 `氢气 6,249,500 / 氧气 16,934,750`。存档库存属于读取时快照，并非 20:01 请求中经过其他组件预占后的完整库存，因此用它重建同形问题，不宣称完整重放当时的 nuke 网络。

修复前，材料方程和循环求解两个回归均耗尽 2,000 次检查点。修复后两者在同一预算内成功，总执行次数 10,683、水需求 32,049,000，并产生一个可重放的紧凑执行步骤。另一个完整规划服务回归在 5,000 次共享检查点内发布成功结果，检查材料来源完整性、原料需求与来源任务先于消费者的调度顺序。原有随机穷举对照继续验证整数最优性。

现场验收应重新请求 `nuke ×1001`：若还有真实缺料，应正常返回材料与循环诊断；若再次耗尽预算，则需检查新的停止组件，不能把本次同形回归当作整个玩家网络的游戏验收。
