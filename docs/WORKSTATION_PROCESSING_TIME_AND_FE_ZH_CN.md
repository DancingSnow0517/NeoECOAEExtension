# 大型集成工作站：加工时间与网络 FE

实施日期：2026-10-24。本文记录本次可进游戏检查的行为，原来的重合配方规则见[配方审计](WORKSTATION_RECIPE_OVERLAP_AUDIT_ZH_CN.md)。

## 时间基准

每条执行路线独立保留材料、输出、加工时间、AE、FE 和额外资源。并行只控制同时加工的份数，单个新批次每个实际加工 tick 最多推进一个时间单位。超频通过提高并行增加吞吐，不再额外压缩加工时间。

有明确时长的配方直接读取时长；只有总能量的配方按来源机器未安装速度卡时的处理能力计算。基础配方最终统一取 `min(原时间, 200 tick)`：超过 10 秒的压到 10 秒，原本不超过 10 秒的保持原值，总能耗与额外材料不变。以下是封顶前的来源基准，而非满升级机器速度：

| 来源 | 基准加工时间 |
| --- | --- |
| 本模组原生配方 | `processingTicks`，省略时为 100 tick，与小型工作站无速度卡时一致 |
| 水晶科技蚀刻、聚合、粉碎及熵变 | `ceil(AE / 200)`，至少 1 tick |
| 闪电科技超载处理，包括借用的高级 AE 路线 | `max(4, ceil(FE / 无速度卡的 FE/t))`，默认 400,000 FE/t；读取已加载的上游配置 |
| 闪电科技装配、模拟 | `max(4, ceil(FE / 200))`；这两台机器的基础速率与超载工厂不同 |
| 高级 AE 反应室、应用发电起源装配器 | 100 tick |
| 扩展 AE、EAEP 晶体合成 | 100 tick |
| 数据重组 | 配方 `duration`，默认 200 tick，即使配方 AE 能耗为零也要等待 |
| 数据充能 | 1 tick |
| 数据一体机、数据充压 | 200 tick |

来源依据：相邻仓库中的 `CircuitEtcherBlockEntity`、`OverloadProcessingFactoryLogic`、`LightningAssemblyChamberLogic`、`LightningSimulationChamberLogic`、`ReactionChamberEntity`、`GenesisSynthesizerBlockEntity`、`FCUtil.speedCardMap`、`SuperCrystalAssemblerBlockEntity.speedFor`、`DataRipperReassemblerRecipeSerializer` 与数据一体机执行逻辑。

例如水晶路线的 57,600 AE 原本对应 288 tick，最终按 200 tick 加工且总耗能仍为 57,600 AE；超载路线的 400,000 FE 保持 4 tick，另收其原本要求的高压闪电。材料相同不表示时间或费用相同。

倍增样板同时同比增加单次样板的时间、AE/FE 和额外资源。例如 4 倍样板占用相同数量的并行通道，持续 4 倍时间，因此不能借倍增样板绕过基础配方吞吐限制。材料、产物仍按样板完整归属记账，不在执行中拆散交回 CPU。

## AE 与 FE 支付

| 执行合同 | 行为 |
| --- | --- |
| 只有 AE | 使用工作站或 AE 网络的 AE 电力 |
| 只有 FE | 优先使用已预留 FE 及安装 `appflux` 时的网络 FE，缺额按当前 AE2 换算率和用电倍率由 AE 代偿；未安装时也可加工 |
| AE 或 FE | 仅在来源机器确实支持 FE 供能时建立；本次用于高级 AE 反应室 |
| AE 加 FE | 支付原有 AE 费用，FE 部分也允许由等价 AE 代偿 |

高级 AE 的 FE 选项按 AE2 当前 FE 换算率与用电倍率计算，未硬编码 1 AE = 2 FE。借用到闪电工厂的反应配方仍遵循闪电原规则：原始数值作为 FE 预算，加高压闪电 1；不能把反应室的 AE/FE 二选一直接带进借用路线。

AE/FE 二选一任务在接收时优先选择 AE；若当前 AE 无法支付第一加工 tick、安装了 Applied Flux 且网络 FE 足以支付该 tick，则选择 FE。选择随任务保存；FE 路径后续也可由 AE 代偿。只有 FE 和 AE 都不足时才暂停，不丢失材料和进度。纯 FE 路线在未安装 Applied Flux 时仍可匹配和执行。

网络 FE 是 Applied Flux 存在 ME 存储中的 FE，不是 AE 能量缓存；GT EU 不会被扣取。AE 网络自身的运行与预热仍需要 AE。成型工作站继续直接访问网络存储，无需给控制器接外部 FE 电缆。

FE 使用 `long` 与整数余数结算，中间乘法使用 `BigInteger`。不足 1 FE 的部分保留到后续加工 tick，不会因每 tick 取整而少付整批能量。AE 与冷却液成功提交后才推进进度并确认 FE 消费。支付失败时，已经从网络取出的 FE 保存在控制器的待结算缓存中，重试可继续使用；缓存与批次的 FE 余数均随存档保存。

## 暂停、旧任务与温控

- 缺能量、额外资源、冷却液、温度条件或输出空间时，保留原有材料与进度；不补算离线加工。
- 完成后等待输出不再支付加工能量。
- 已经接收的旧版本任务保留原来的 200 步与旧推进方式；更新后接收的新任务使用独立时间合同，不中途重新定价旧任务。
- 温度模式下按每个实际工作 tick 的占用负载产热，不会因总时间变长而自动将每 tick 热量除以总时长。
- 冷却液模式仍在超频批次实际推进时消耗 100 mB/t。例如单倍样板稳定推进 200 tick 对应 20,000 mB；空闲与支付失败时不消耗该加工 tick 的冷却液。温度模式的主动冷却继续按自身温控规则运行。

## JEI、EMI 与工作站界面

查看器上方保留代表配方的材料批量，下方只显示一组信息：耗能、加工时间，以及存在额外资源时的“额外需要”。有 Applied Flux 时，FE 配方优先显示 FE；未安装时显示可实际支付的等价 AE。AE 单位为紫色，FE 单位为深绿色。

Tooltip 按升级卡分段，标题使用对应 Mod 的主题色，耗能、加工时间、额外需要各占一行。相同批量不重复，批量不同的路线单独注明产出。普通提示去掉长配方 ID 和大段说明，FE 供能说明统一放在底部两行。悬停右侧卡片仅显示该卡支持的方案。

大型工作站 JEI 物品输入与输出槽的数量字体缩至原来的 70%，并限制在槽内；从 1,000 起使用最多三位有效数字的 SI 缩写，例如 `1K`、`8.19K`，物品 Tooltip 显示完整的千分位数量。

升级卡始终位于信息区域右侧；页面高度只随摘要行数和卡片行数增加，不再按加工路线展开，不挤到文字左侧或覆盖材料槽。JEI 与 EMI 共享布局。

工作站能源提示分别显示实际 AE/t 与网络 FE/t、待结算 FE；AE 代偿计入 AE/t，不能把代偿部分记作已扣 FE。任务提示显示实际加工 tick 与总时长。

原生 JSON 可增加 `"processingTicks": 40`；Java builder 使用 `.processingTicks(40)`，KubeJS 同名方法可用。自定义运行时适配器使用 `recipe.processing(ticks, feEnergy, feAlternative)`，其中 `recipe.energy()` 表示 AE 预算；FE-only 应将 AE 预算设为零。旧的 Java 构造方法继续有效。

## 游戏内检查

1. 核对面板只保留耗能、加工时间和适用时的额外需要；检查能源单位颜色、按卡分段的 Tooltip、物品数量缩写与完整数量提示。
2. 未安装 Applied Flux 时，闪电路线应扣等价 AE 与原始闪电，面板显示 AE；安装时优先显示 FE 并提取网络 FE，只有缺额用 AE 代偿。
3. 分别抽空 FE、抽空 AE、同时抽空两者，观察代偿、暂停及补充后续作；网络只剩部分 FE 时，不能重复扣取整笔 FE 或整笔 AE。
4. 用高级 AE 反应室路线，在 AE 不足且网络 FE 足够时接收新任务，观察 FE/t；单独向网络补 AE 则可使用 AE 路线。
5. 测试翻倍样板、存档重进、加工中断电、输出受阻及冷却液不足。观察时间、能源总额和产物都不重复。
