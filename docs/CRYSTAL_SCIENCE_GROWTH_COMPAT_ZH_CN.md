# 大型集成工作站：水晶科技晶体催生仓兼容

实施日期：2026-10-26。源码依据为水晶科技 `origin/1.21.1` 的 `3916c001`，读取前已从上游更新。适用 Minecraft 1.21.1。

## 使用方式

在大型集成工作站中安装现有的水晶科技升级卡，用加工样板输入种子、输出相应高纯晶体即可。每个种子产出一个晶体，不消耗水。催生配方会进入工作站的 JEI / EMI 配方列表，来源名称为“水晶科技：晶体催生”。

已生长一部分的种子也可作为输入；费用和时间仍按完整催生周期计算。翻倍样板沿用现有工作站规则，同步增加材料、时间和能量；并行控制同时加工的操作数量。

## 来源规则与费用

晶体催生仓没有注册普通配方类型。`CrystalGrowthChamberBlockEntity.serverTick()` 对 `ae2cs:crystal_seeds` 标签内的种子调用 `CrystalSeedItem.grow()`；后者从种子实例读取 `getGrowTo()` 和 `getOvergrowTick()`，并保留原堆叠数量。

无升级、没有相邻催生器时，催生仓每 10 tick 推进 10 个生长刻，每个工作循环消耗 100 AE。工作站将单个种子定义为一个加工操作：

- 工作循环数：`ceil(生长刻 / 10)`。
- 每个种子的总耗能：`工作循环数 × 100 AE`。
- 基础时间：`min(工作循环数 × 10 tick, 200 tick)`。
- 默认种子需要 600 生长刻，因此每个操作消耗 6,000 AE、加工 200 tick，产出 1 个对应晶体。

原催生仓一次付费会共同推进多个槽位的种子。大型工作站采用每个种子独立计费，不继承原仓整仓共享费用，也不借用加速卡、超载卡或相邻催生器的增益。其超频和冷却继续由大型工作站自己的机制决定。

## 加载与存档

只有注册了 `ae2cs:crystal_growth_chamber` 物品时才收集配方，输入来源与原仓一致，读取已加载的 `ae2cs:crystal_seeds` 标签。每个真正的 `CrystalSeedItem` 都读取自己的产物与周期，不硬编码 17 种内置种子的映射。没有安装水晶科技时，无需加载任何可选 Mod 类。

配方是大型工作站运行时合同，不写入第三方配方管理器。执行 ID 为 `neoecoae:crystal_growth/<种子命名空间>/<种子路径>`，参与按卡筛选、材料分组和保存批次的 ID 恢复。标签更新沿用现有缓存失效处理。若 ID 与真实数据包配方冲突，保留真实配方并跳过该催生别名。

未知子类、非法周期或空产物不生成配方；一个种子失败不影响其他合法种子。这样可避免上游改变规则时静默生成错误材料或费用。

## 验证范围

回归测试使用发布版水晶科技的真实 `CrystalSeedItem` 类，覆盖默认和自定义周期、数量比例、已有进度、翻倍费用、非法输入、缺失可选 Mod、按卡筛选、原 ID 恢复、缓存失效和 ID 冲突。测试依赖仅在 JVM 测试运行时加载，不进入发布 JAR。

游戏内加工与 JEI / EMI 画面需要另行验收。
