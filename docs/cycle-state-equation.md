# 循环规划：状态方程与执行证明

生产入口统一使用 `BoundedCycleSolver`。单样板增长、严格环和分裂／合并循环都先进入
`CycleStateEquation`；旧的 `SinglePatternGrowthCycleSolver` 只保留调用兼容，独立增长计算器不再负责生产路径分流。

对每个不允许从外部导入的具体 AEKey，建立
`stock + (produced - consumed) * x >= required`，要求 `x` 为非负整数，目标是最小化总执行次数。
外部边界原料不受这层库存约束，仍由外部 DAG 验证真实供给。上层继续用库存加新增需求表示最终产物订单。

线性松弛使用 BigInteger 有理数的两阶段单纯形法，整数部分使用有界分支定界。
只有松弛严格无解或全部整数分支关闭才返回不可行；节点、枢轴或有理数位数达到上限不构成材料不足证明。
这也使“某个库存可以无限增长，但另一个守恒资源不足”无需穷举无限状态空间。
整数优化预算未耗尽时，返回最少执行次数向量；预算耗尽但已有可行向量时，可继续验证该向量，不能声称最优。

次数向量只是必要条件。构造器按实际可投料批次执行，计算一圈前缀缺口并压缩安全重复，最后统一回放种子、边界导入和产物余额。
不安全的静态语义或耐久变更不进入代数重复路径。无法构造顺序时仍回退到有界搜索；一个构造顺序缺种子不能证明其他顺序不可行。
启动候选须先验证实际外部供给，再用新库存重新求解。

搜索缺口按每个具体物品／流体的 `缺口 / 需求` 比例比较；种子候选和边界原料的启发式成本也不再直接相加不同单位。
比例使用百万分之一精度的定点数，只影响搜索顺序，不参与可行性证明。

默认不再按 8 个 key 自动升级到百万状态。预算按标记宽度、样板数及竞争生产／消耗关系估算，
单次搜索和种子梯度共用最多 100,000 个状态，全订单仍受 `ECOPlanningBudget` 时间／工作量限制。
256 个 key、64 个样板只是结构安全上限，不代表搜索必定完成。显式传入的调用方预算仍生效。

合成报告中，库存中性种子的 Tooltip 显示本计划预留份数支持的并发占用上限。
批次会显式预留实际使用的现有催化剂；不同机器、执行顺序和投料能力仍可能降低实际吞吐。
更多种子库存可在重新规划时形成更大的批次。当前未添加玩家手动指定种子预留量的控件。
该字段随合成报告数据包同步，服务端与客户端需使用同一版本。

回归覆盖：小规模整数最优解与独立穷举对照、分数解不可行、超出 double／long 的精确数量、
有限燃料与无限增长、单状态预算下的分裂／合并大订单、种子死锁、现有执行／NBT 重复计划以及并发提示的数据包往返。
