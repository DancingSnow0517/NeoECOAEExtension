循环样板规划与执行

循环规划使用编译后的 AE 物理样板、精确 AEKey、样板倍率和已规范化的返还物。物品组件不同的工具不是同一个种子；物品数量与流体数量也不会在种子候选支配比较中互相抵消。

对于桶、容器、催化剂和多产物反馈形成的固定配方顺序，规划器记录一轮需要的初始库存、净变化、总产出和每个物理样板的执行次数。只有已证明可按顺序执行的配方段才能重复。有限燃料、消耗型载体及循环中的临时库存峰值都会限制可重复次数；外部输入仍由外部配方规划和材料事务实际供应。

例如两张样板：

```text
空桶 + 1000 mB 水 -> 水桶
水桶 -> 产品 + 空桶
```

只持有一个空桶、请求万亿个产品时，执行计划保存两段样板和万亿次循环计数，供水需求仍是 1000 × 万亿 mB。CPU 按“装桶、使用、装桶、使用”的顺序发配，不会把第二轮的空桶当成已经到货。部分接收只扣除实际被供应器接收的次数；供应器拒绝、材料未回流时不推进顺序。实际加工时间仍取决于机器和物流。

`PatternRun` 和 `ECOExecutionPlan.ExecutionStep` 的 `count` 是每轮次数；最后一段的 `repeatWidth` 表示包括自身的循环段数，`repetitions` 表示总轮数。普通段默认 `(repeatWidth=1, repetitions=1)`。循环段不重叠、不嵌套。统计总次数时必须包含重复倍率，不能再只把所有 `count` 相加。

存档同时保存计划的循环边界以及运行时剩余轮数。重载时还会用已接受的任务计数复核游标，整轮进度通过算术跳过，不会按万亿次遍历。旧存档中没有重复字段的普通有序步骤按一轮读取。

启动不足时，规划器按完整执行顺序的前缀库存缺口计算所需种子和消耗，不再做固定次数的指数倍增探测。同时保留按具体物料键比较的全部非支配启动候选，不截取前 32 项。候选本身只是建议。恢复阶段先验证额外种子确实可由库存或外部样板供应，再重新验证循环，并校验该执行顺序的完整外部消耗。已有种子会被保留，不能再次算成新增供应；失败探测不提交样板次数或材料消耗。

已证明静态安全的精确样板和已绑定具体材料的替代样板可以使用循环压缩。未知或模糊匹配、未证明静态安全的返还行为以及耐久变化样板不使用此压缩路径。复杂竞争路线仍保留有界库存搜索；没有通用整数求解器依赖，也不把单纯的投入产出平衡当作可执行证明。

已验证的单样板自增长优先调用闭式整数计算器，再使用公共见证回放核算有限燃料、外部供给和种子。其他静态循环先求精确有理数状态方程，并对整数分支定界；不再限制 pivot 数、分支节点数或整数位数。恒等约束和由非负执行次数直接保证的约束会被消去。

见证构造和周期加速没有固定宏步数或 32 步视距。后缀摘要增量合并，重复次数同时受库存前缀需求、有限消耗和剩余执行向量约束，不能超额执行。库存搜索使用同一个优先队列保留备选路径，周期跳跃与普通单次、目标边界和解锁边界批次共同参与搜索，不再先做一段可能被前瞻预算全盘丢弃的贪心探测。

常规配置的 `[fastPath]` 节新增：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `ecoPlanningMaxMillis` | 10000 | 一次 ECO 规划会话的协作式总耗时预算，单位毫秒 |
| `ecoPlanningMaxWork` | 5000000 | 一次规划会话共享的检查点工作量预算 |
| `ecoPlanningMaxMemoryMiB` | 64 | 一次循环求解保留矩阵、见证和搜索状态的估算内存预算，单位 MiB |

结构编译、路线选择、外部种子供应、循环搜索以及 AE 的 CRAFT_LESS 数量探测共用时间和工作量预算。内存预算按数组、节点、矩阵及大整数的保守尺寸估算，并非 JVM 堆测量，也不替代整合包的整体内存配置。预算耗尽返回 `CYCLE_UNRESOLVED` 并记录预算诊断，不报告已证明缺料，也不生成可提交的半成品计划。玩家取消仍使用独立的取消状态。

默认不设样板数、物料键数、状态数、执行深度和路线尝试次数门槛。`CycleSolveLimits` 保留调用者显式指定的结构、状态和深度限制以兼容集成与测试；零表示由资源预算管理。旧 `maxSeedLadderSteps` 字段仅保留源码兼容，不再驱动倍增探测。100000 次的旧见证展开阈值仍然保留：它仅控制是否额外生成逐次列表，完整执行证明始终保存在压缩计划中，不影响可解性。AE2 执行字段的 `long` 表示边界也仍然保留，理论计数使用任意精度整数，不截断或饱和。

回归用例覆盖万亿级桶循环、流体计账、催化剂与多产物、有限燃料、空种子、外部可制作的替代种子、部分接收、NBT 往返、超大进度恢复、旧路线缺料缓存以及共享预算。游戏内机器与其他模组供应器的端到端性能仍需通过实际整合包验证。
