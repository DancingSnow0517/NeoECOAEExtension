# ECO BigInt 父订单与安全 long FastPath

父任务进度使用 BigInteger；ICraftingPlan、GenericStack、当前 ExecutingCraftingJob 和 AE2 原生包仍为 long。ECOBigOrderRequest 是独立的父任务元数据，不实现 ICraftingPlan。

## 提交与执行

- 完整但 long 无法表示的 ECO 结果可由 ECO CPU 提交。自动 CPU 选择仅在这一入口查找 ECO CPU；明确选择其他 CPU 时拒绝。
- Shift + MISSING_ITEMS 可以创建等待订单。其他不完整、循环未解、语义不支持和内部错误结果不允许进入父订单。
- 客户端只发送菜单编号和 Shift 意图，服务端读取当前确认结果、规划选项、目标和 CPU。
- 每次在新的库存/Provider 图上异步规划一个候选；数量、bytes 或材料不满足时将整个候选减半，直至找到完整子计划或无法启动。
- 当前 Provider revision 下缓存最近成功段大小。图版本变化时不复用上限；异步结果返回时若图版本已改变则重算。
- 子段逐段更新集群 bytes 预留。父订单等待时保留 CPU 线程，不占用下一段未取得的 bytes。
- 等待重试为 20、40、80、160、200 tick，之后保持 200；成功规划重置退避。
- 最终输出已交付且子计划完整完成后才累加 completed。中间段不终结 CraftingLink，也不发送父完成事件。
- 余料先回存网络；网络无法接收时保留在 CPU 并等待，避免下段重复抽取库存。
- 原下单玩家不在线时，新一段等待该玩家上线，以免恢复后改用机器权限。已运行的子段继续原有执行流程。
- 取消终止规划 Future，并先记录 Worker 终止决定、恢复可恢复输入，再取消父 link。
- NBT 保留父 UUID、精确数量、状态、退避和选项；已有子任务的执行账本继续使用原存档格式。十进制数量上限为 1024 字符。

## FastPath

材料上限按 long 可表示范围动态计算，包括重复键合并、输出和容器余料共享的等待键以及现有等待库存。非零单批能量不超过 2^52；零能量不受该上限约束。缩放和合并使用精确算术，Provider 能力仍参与上限选择。物理 Worker 的批次数和槽位仍保持 int。

## 验证记录

自动化测试覆盖精确累计、退避、恢复、提交状态白名单、完整候选降阶、单一父 link / 完成事件、超旧上限批次、余料/等待库存合并、能量精度和既有 Provider 拒绝回滚协议。

执行命令：

```powershell
.\gradlew.bat test
.\gradlew.bat build
```

客户端启动检查目前被既有 Jade 依赖版本冲突阻止：clientLegacyClasspath 请求 8591319，但 runtimeClasspath 一致性约束为 5444008。以下游戏内项目尚未验收：

1. 用会使中间物料或 Pattern 次数超 long 的完整规划打开确认页；ECO CPU 可开始，显式非 ECO CPU 禁用并提示。
2. Shift 提交缺料父订单，观察等待状态，补充材料后确认恢复执行。
3. 在状态页切换 CPU、关闭并重新打开，确认叠层没有遗留的 UUID/进度。
4. 第一段完成后确认父任务仍在，下一段使用变化后的库存和 Pattern。
5. 分别在规划等待、子段运行、输出等待时取消；确认输入恢复、Worker 不继续执行、父 link 终止。
6. 子段运行中保存退出并重启，确认相同 UUID 与完成量，没有重放已完成段。
7. 在全虚拟环境验证超过 2^42 的批次和能量限制；物理 Worker 仍按 int 批次。
