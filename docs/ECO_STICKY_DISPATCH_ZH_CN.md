# ECO 配方粘性调度

适用于输入格数量有限、单格容量较大的加工机器，减少多个配方共用机器时过早轮换造成的投料中断。

- 配方派发成功后，下一次优先选择同一配方；每次仍重新获取合法候选，执行原有缺料、依赖、循环和预算检查。
- 每个配方的连续派发上限从 8 次开始。跑满本轮上限后，先按原有候选顺序让位，下轮再按 `8 → 16 → 32` 增长，最高 32 次。本轮上限保持固定。
- 调度器收到一次成功的批量派发结果记一次，不按合成数量计数，也不把同次自适应投料的内部批次分别计数。
- 整个配方派发失败、缺料或没有可用提供者时立即让位，下一轮上限减半，最低 8 次。某个提供者拒绝后，仍先尝试该配方的其他提供者；其中一个成功即可继续本配方。
- tick 结束或预算用尽仅暂停，保留连续计数和学习到的上限；没有实际提交的批量尝试不作为派发失败处理。
- 配方完成或退出合法候选时释放粘性；调度状态重置时清空连续计数和学习到的上限。

批量智能翻倍仍负责一次投多少，配方粘性负责成功后先选谁。原有的物料事务、自适应退让、任务依赖和提供者轮转继续执行。粘性状态只保存在当前 CPU 的调度内存中，不增加存档字段。
