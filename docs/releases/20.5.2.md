## 中文

对比版本：`20.5.1`

适用版本：Minecraft 1.20.1 / Forge

**本次新增 KubeJS 配方与 ECO 内置大宗压缩存储，修复专服工作站和公共界面分端问题，并优化合成规划与大型存储网络。大型集成工作站实际运行批次固定为 1 tick。**

### 新增

- 支持通过 KubeJS 定义大型集成工作站加工配方与冷却配方，支持链式设置物品、流体、能耗和加工时间。
- 存储主机中右键存储盘可打开操作菜单：大宗盘可预览并确认“标记并迁移”，每块盘可单独设置相对主机的优先级。
- 合成流体输入仓与输出仓新增稳定的流体处理器访问方法，供附属调用。
- 补充 Forge 1.20.1 中英文 API 接入指南和项目 README，提供版本依赖、下载入口与接口说明。

### 调整

- 大型集成工作站运行时每批配方固定为 1 tick；JEI/EMI 仍展示配方原本的加工时间，实际吞吐由并行数量决定。
- 大宗压缩由 ECO 内置实现，不再依赖 MEGA Cells 的压缩功能。系统自动识别可逆工作台压缩链，也可通过数据包 `data/<命名空间>/eco_compression/*.json` 添加或排除关系；转换产物先保存在盘内，再回存网络。
- Bigger AE2 数字奇点物品矩阵接入大宗压缩：默认 5 类资源，安装 ECO 大宗扩展卡后 25 类，数量无上限，悬浮提示显示类型用量和压缩状态。
- 旧 ECO 大宗存储矩阵（MEGA Cells）保留读取兼容并显示弃用提示，不再提供组装与拆解配方；ECO 大宗扩展卡改用 AE2 与 ECO 材料合成。

### 修复

- 修复 Applied Mekanistics 化学品回存遇到错误能力类型时可能崩溃的问题，保留资源并允许网络继续尝试其他存储位置。
- 修复联机客户端首次打开方块界面时 UI 工厂未注册的问题，并避免专用服务器注册界面时加载客户端类。
- 修复循环增殖配方在库存刚好满足下游需求时未保留启动种子的问题。
- 完善 KubeJS 配方的默认能耗、物品输入数量及流体标签匹配。
- 修复 #144：共享纹理、工作站公共 UI、菜单 reader 和计算滚动条在专服初始化时加载客户端类的问题，保留客户端绘制与交互。
- 打开工作站界面时同步服务端方块状态，避免客户端块状态更新滞后导致普通/大型界面的控件树不一致；同位置替换机器后，旧菜单立即停止处理按钮和槽位操作。
- 数字奇点物品矩阵首次访问时自动迁移旧格式的精确库存，保留超出 long 范围的数量，重载后保持一致。
- 大宗标记查重覆盖全网所有大宗盘，迁移时不会从其他大宗矩阵抽取库存；盘内仍有待回存的转换产物时不能拆解。
- 普通合成与大订单提交抛出运行时异常或链接错误时，确认界面现在会反馈错误，并记录完整异常日志，便于定位点击开始后没有反馈的问题。

### 优化

- 提前识别循环配方缺少启动物的死锁，减少无效搜索。
- 优化合成规划与超大存储的精确数量运算，降低常用数量范围内的计算开销。
- 按存储挂载变化增量刷新 AE2 网络库存缓存，减少存储查询与服务端存储域管理的锁开销。
- 优化 MEGA 解压输出缓存，减少处理开销。

### 说明

- 此次替换 GitHub 上早期的同名 `20.5.2` 构建。客户端和服务端必须一起更新，不能与旧同名构建混用；新的网络握手会拒绝不兼容的组合。
- 1.20.1 暂未提供从存储主机远程打开元件工作台调整资源类型的功能。
- 旧单类型 ECO 大宗物品存储矩阵（16M/64M/256M）保持原有存储方式，不参与压缩。
- 提交异常反馈改进不代表所有 ECO CPU 接单失败的根因均已修复；不会自动重试或切换目标 CPU。

## English

Compared with: `20.5.1`

For Minecraft 1.20.1 / Forge

**This release adds KubeJS recipes and ECO's built-in bulk compression, fixes dedicated-server workstation and shared UI issues, and improves crafting planning and large storage networks. Large Integrated Workstation runtime batches now take 1 tick.**

### Added

- Add KubeJS support for Large Integrated Workstation processing and cooling recipes, with chained methods for items, fluids, energy, and processing time.
- Right-click a cell in the storage host to open its actions: bulk cells can preview and confirm "mark and migrate", and every cell can have its own priority relative to the host.
- Crafting fluid input and output hatches provide stable fluid handler accessors for addons.
- Added English and Chinese Forge 1.20.1 API guides and project READMEs with dependencies, downloads and integration documentation.

### Changed

- Large Integrated Workstation runtime batches take 1 tick. JEI/EMI still show each recipe's original processing time; throughput depends on parallelism.
- Bulk compression is built into ECO without relying on MEGA Cells compression. Reversible crafting chains are detected automatically; datapacks can add or exclude conversions in `data/<namespace>/eco_compression/*.json`. Outputs stay on the cell until the network accepts them.
- The Bigger AE2 Digital Singularity Item Storage Matrix uses bulk compression: 5 resource types by default, 25 with an ECO Bulk Expansion Card, with unlimited quantities. Tooltips show type usage and compression status.
- The old ECO Bulk Storage Matrix (MEGA Cells) retains read compatibility with a deprecation notice and no longer has assembly or disassembly recipes. ECO Bulk Expansion Cards now use AE2 and ECO materials.

### Fixed

- Fix crashes when Applied Mekanistics returns chemicals to a block exposing an incompatible capability type. Resources are preserved so the network can try other storage destinations.
- Fix missing UI factory registration when a multiplayer client first opens a block interface, and avoid loading client classes during dedicated server UI registration.
- Fix cyclic production recipes failing to retain a startup seed when available stock exactly meets downstream demand.
- Improve KubeJS recipe defaults for energy, counted item inputs, and fluid tag matching.
- Fix #144: shared textures, workstation UI classes, menu readers and computation scrollbars no longer initialize client-only classes on dedicated servers. Client rendering and controls are retained.
- Synchronize the server's block-state snapshot when opening workstation menus so delayed client world updates cannot select a different ordinary/large widget tree. Replacing a machine at the same position immediately blocks the old menu's button and slot actions.
- Digital Singularity Item Storage Matrices migrate old exact contents on first access, preserving amounts beyond long across reloads.
- Bulk marker duplicate checks cover all bulk cells in the network, and migration never extracts from another bulk matrix. Cells with conversion outputs waiting for network storage cannot be disassembled.
- Runtime exceptions and linkage errors during ordinary or big-order submission now reach the confirmation screen and produce full exception logs, helping diagnose submissions that previously gave no feedback after clicking Start.

### Improved

- Detect cyclic recipe deadlocks caused by missing startup materials earlier, reducing unnecessary searches.
- Optimize exact quantity arithmetic for crafting planning and very large storage, reducing overhead for common quantity ranges.
- Refresh AE2 network inventory caches incrementally when storage mounts change, and reduce locking overhead in storage queries and server storage domain management.
- Reduce processing overhead in the MEGA decompression output cache.

### Notes

- This replaces the earlier GitHub build carrying the same `20.5.2` version. Update both client and server together; old same-version builds are incompatible and will be rejected by the new network handshake.
- 1.20.1 does not yet open the cell workbench remotely from the storage host to adjust resource types.
- Old single-type ECO Bulk Item Storage Matrices (16M/64M/256M) keep their existing storage and do not use compression.
- Submission exception feedback does not establish that every ECO CPU admission failure has been fixed. It does not automatically retry or switch the target CPU.
