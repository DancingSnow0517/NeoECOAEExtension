## 中文

对比版本：`20.5.2`

适用版本：Minecraft 1.20.1 / Forge

**本次优化无限存储迁移与库存刷新，更新 JEI/EMI 多方块预览，并修复循环合成、连续派发及 GT/GTL 批量加工兼容问题。**

### 新增

- 存储主机界面显示无限存储迁移百分比与受阻原因，便于识别不可读、只读或写盘失败等情况。
- JEI/EMI 多方块预览采用新面板，提供长度调整、分层和成型切换按钮；材料列表支持按整行滚动。
- 多方块预览按单台结构的实际组件显示计算并行、容量、线程，合成理论速度、批量和核心数，以及存储和工作站信息。

### 修复

- 修复循环合成为保留启动种子而额外增加加工次数的问题；在不增加样板执行次数时继续保留种子，并允许后台优化减少工作量。
- 已成功派发的样板在后续回调及预算暂停后保持派发优先级，减少连续加工被打断的情况；缺料、供应器忙碌或拒绝、任务暂停或结束时释放优先级。
- 将 GTL 分子装配室纳入批量加工，使用原始样板与原生容量检查，保留工具校验与正确的产物计数。
- 兼容缺少强制合成协议的旧版 ExtendedAE Plus，回退使用 ECO 的强制合成实现。
- 修复工作站成型预览模型缺失、切换场景后残留旧分层过滤，以及材料数量的字体、阴影和定位问题。
- 适配 JEI 15 多方块分类页面高度，切换普通配方时恢复用户的页面高度。

### 优化

- 无限存储迁移按驱动器位置顺序执行，每台主机共享每 tick 的时间预算与资源种类上限，减少迁移对服务端的集中开销；保留旧迁移回执兼容性。
- 无限存储变更按资源增量刷新网络库存，变更记录过期或可见性变化时自动回退到完整刷新。
- 合并驱动器重复的持久化通知，减少高频传输中的方块更新开销。
- 加工调度预算改按接口提交次数计算：每个 CPU 每 tick 最多 64 次提交，单个配方最多 32 次，不再以百万份合成数量作为每 tick 上限。
- GT/GTL 样板总成及 GTL 分子装配室按其原生 long 容量批量接单，可处理超过 `Integer.MAX_VALUE` 的单次加工份数；预算用尽不会将供应器误判为失败或触发退避。

### 说明

- 多方块预览中的合成速度为理论值，实际吞吐仍取决于供料、能源、冷却与执行端状态。
- 本次补充了盈能水晶掉落回归测试；整合包中普通铁镐挖掘掉落本体的反馈尚未定位修复。

## English

Compared with: `20.5.2`

For Minecraft 1.20.1 / Forge

**This release improves infinite storage migration and inventory refreshes, updates JEI/EMI multiblock previews, and fixes cyclic crafting, continuous dispatch, and GT/GTL batch processing compatibility.**

### Added

- The storage host interface displays infinite storage migration progress and blocking reasons, including unreadable or read-only storage and write failures.
- JEI/EMI multiblock previews use a new panel with length, layer, and formed-state controls. Material lists scroll by complete rows.
- Multiblock previews show computation parallelism, capacity and threads, theoretical crafting speed, batch capacity and core count, and storage/workstation information based on the components in one structure.

### Fixed

- Fix cyclic crafting adding extra processing steps just to retain a startup seed. Seeds are retained when doing so does not increase pattern execution counts, and background optimization can continue reducing work.
- Successfully dispatched patterns retain dispatch priority across subsequent callbacks and budget pauses, reducing interruptions to continuous processing. Priority is released when materials are missing, a provider is busy or rejects work, or the job pauses or ends.
- Include GTL Molecular Assembly Rooms in batch processing, using the original pattern and native capacity checks to preserve tool validation and correct output counts.
- Fall back to ECO's forced crafting implementation with older ExtendedAE Plus versions that lack the forced crafting protocol.
- Fix missing formed workstation preview models, stale layer filters after scene changes, and material count font, shadow and positioning.
- Adapt multiblock category height to JEI 15 and restore the user's page height when switching to ordinary recipes.

### Improved

- Infinite storage migration processes drives in position order with a shared per-host time budget and resource-type limit each tick, reducing concentrated server work while retaining compatibility with existing migration receipts.
- Refresh network inventories incrementally for changed infinite storage resources, falling back to a full refresh when change history expires or visibility changes.
- Combine duplicate drive persistence notifications and reduce block updates during frequent transfers.
- Processing dispatch budgets now count interface submissions: up to 64 per CPU per tick and 32 per recipe. The previous million-craft per-tick limit is removed.
- GT/GTL Pattern Assemblies and GTL Molecular Assembly Rooms accept batches according to their native long capacity, including individual submissions larger than `Integer.MAX_VALUE`. Exhausting the dispatch budget no longer marks a provider as failed or triggers backoff.

### Notes

- Crafting speed shown in multiblock previews is theoretical. Actual throughput still depends on materials, power, cooling, and execution conditions.
- Energized crystal loot regression tests were added. The reported modpack issue where mining with a normal iron pickaxe drops the block itself has not yet been diagnosed or fixed.
