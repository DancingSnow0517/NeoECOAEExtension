# 规划器挑战修复报告（2026-10-19）

原有 26 个科技配方场景现在全部符合独立证明：**24 个可行场景成功，2 个不可行对照正确拒绝**。修复前的 6 个漏解全部消除。26 项独立证明与 26 项规划挑战合计 **52 项全部通过**，配方、库存、订单量与成功断言保持原义。

本轮沿用 **120000 ms、50000000 工作量检查点、64 MiB 循环内存估算预算**。修复通过补齐启动候选、执行顺序与收尾计算实现，没有增加预算。原始配方和失败证据见 [挑战基线报告](PLANNER_CHALLENGE_REPORT_2026_10_19_ZH_CN.md)。

## 1. 启动补酸与回收循环

`BoundedCycleSolver` 原先只从初始库存收集不能执行的配方缺口。现在会在真实可达状态搜索中收集已执行前缀后的阻塞缺口，按完整物料 Key 保留互不支配的补料候选。因此酸洗已经能执行一次时，仍能提出补 500 mB 盐酸的候选，供原有外部供料与完整循环验证流程使用。

3 单最小案例还暴露了第二个问题：净增循环的一轮把两次酸洗压成一个批次，原来的收尾计算只考虑整个批次边界，导致做 3 份产物也要求 4 份矿粉。现在能用整数公式计算最后批次只执行几次，再完整验证该前缀的种子、净产出及有限输入。

最终最小案例实际执行次数为：

- 制酸 1 次。
- 酸洗 3 次。
- 回收 1 次。

预留恰好为原库存中的矿粉 3、盐酸 500 mB、水 1000 mB、制酸试剂 1。执行计划可以从这些真实预留材料逐次执行完成。64 单以及改变样板顺序的案例也全部通过。

候选仍然只是建议：外部配方必须真实存在、原料必须足够，并重新验证整个订单。缺少制酸试剂的对照仍然拒绝，禁止无依据重入当前循环的规则继续生效。

## 2. 返还工具的混合路线与预留

`JointRouteOptimizer` 允许精确、一进一出、完整 Key 不变的返还工具进入有序联合求解。工具返还量进入物料平衡，正常产品仍须符合 AE 的生产者发布契约；返还工具本身不会成为虚构的可合成产物。

这类方案统一使用有序物理回放确定启动库存。原来的聚合消耗算法即使在数学上得到零净消耗，也可能先按执行次数预留很多把工具；改为按整条顺序计算所需的工作副本后，两条原料路线可以依次复用同一把。

实测：A、B 各 32，订单 64 时，两条路线各执行 32 次，只预留工具 1。库存有 2 把或 64 把工具的回归也只预留 1 把，其他副本留在 ME 库存中。缺工具、工具组件不匹配的对照均不会成功。

这项策略优先保证其他任务能使用剩余种子。原样返还工具不会在任务内增殖，只预留一把时，该任务同时使用这一工具的并行上限也为一；机器吞吐仍受实际预留量和执行顺序约束。

该路径要求编译输入返还量与语义分析中的返还量完全一致。耐久变化、容器转换、模糊匹配等继续由对应路径处理，没有把它们视为原样返还。

## 3. 扩培启动性能

原来的整数次数见证构造按最大安全批次执行分离，将培养液全部转成菌种后，产酶配方又缺培养液；随后反复补入假设种子，产生大量不能直接用于当前库存的中间见证。

现在针对下一条仍需执行的配方，解出当前批次能够让其所有有限输入同时可用的整数区间，在该区间内保留尽可能大的批量。这样既可保留下游启动材料，也能继续压缩重复执行，不需要按订单数量枚举库存状态。

这些时间是本机单次 JVM 测量，不代表服务器 TPS 或机器合成速度；小订单没有稳定加速的证据。大订单的确定性变化是检查回调数降至 1826，且 1024 至 1000000 的几档不再随订单量增长。常规回归还约束这些扩培案例少于 100000 次检查，并保留紧凑执行计划。

## 5. 复现

在仓库根目录运行完整挑战：

```powershell
.\gradlew.bat '-Dplanner.challenge.enabled=true' '-Dplanner.challenge.profile=default' test --tests 'cn.dancingsnow.neoecoae.crafting.planner.solve.TechModPlanner*Test' --console=plain
```

运行规划器、执行器与种子同步回归：

```powershell
.\gradlew.bat test --tests 'cn.dancingsnow.neoecoae.crafting.planner.*' --tests 'cn.dancingsnow.neoecoae.crafting.execution.*' --tests 'cn.dancingsnow.neoecoae.network.CycleSeedParallelismSyncTest' --console=plain
```

本轮生产代码修复集中在 `BoundedCycleSolver` 和 `JointRouteOptimizer`；保留已有快速增殖、可行解优先、种子保留偏好及必要回退行为。
